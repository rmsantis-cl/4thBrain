2. **Story 12.2 (Schema Redesign) — designed, then explicitly approved for implementation, then applied and tested.** Final schema (`documets/design/schema.sql`, real file, already committed):
   - Natural keys (`name TEXT PRIMARY KEY`, no surrogate id) on `status`, `job_type`, `job_status`, `tag`, and **`classification`** — classification is globally name-unique across the whole tree (not per-parent), and doubles as a registry of known system directory roles (`VAULT_DIR`, `VAULT_RAW`, `VAULT_INCOMMING`, `DOCUMENT_ROOT`, `TMP_DIR`), each meant to resolve to a real path via a matching **uppercase** key in `params.json` — **not yet applied to the live `params.json`**, still just documented in `documets/PLAN-28-08-2026.md`.
   - `document`, `job`, `job_file` use `id INTEGER PRIMARY KEY` (SQLite rowid autoincrement) — no UUIDs anywhere.
   - `tag` is never hard-deleted — "removing" a tag sets `end_date`/`active=false`; the row survives so nothing FK'd to it (`document_tag.tag_name`) is ever orphaned. `tag.name`/`status.name`/`job_type.name`/`job_status.name` are treated as immutable once created — no repository should expose an in-place rename; renaming means retiring the old row and inserting a new one.
   - New `job_status` table (mirrors `status`, seeded New/Running/Completed/Failed) — `job.status` previously had no FK at all.
   - New `job_file` table (name, path, mime_type, directory, `job_id` FK, unvalidated `status`, `lock_by_PID`).
   - Tested directly against a scratch SQLite DB: schema applies cleanly, constraints correctly reject bad data (duplicate classification name, invalid job status), tag soft-delete confirmed working.
   - `documets/design/classes.md` re-baselined to match exactly (8 entities: Document, Status, Classification, Job, JobType, JobStatus, JobFile, Tag — `Process`/`JobDocument` removed).
   - Root `CLAUDE.md` rewritten: corrected the stale "no application code yet" claim, restructured to point at `PROJECT-SUMMARY.md` for status instead of duplicating a snapshot (the duplication is exactly what caused this staleness in the first place).
