# Story 6.1 Pipeline Gap — Design & Correction Plan

## Problem Statement

Story 6.1 ("Web Ingestion Form & Submission Handler") is marked **Completed**, but the acceptance criteria is hollow:

**AC:** "Submitting form content creates a valid pipeline job and returns a unique Job ID immediately."

**Technical status:** ✅ Met — forms work, jobs are created in database, Job IDs returned.

**Actual system status:** ❌ Broken — jobs sit in the database with no pipeline processor consuming them. The ingestion pipeline (Story 4.1, EP4) is not implemented, so submitting a form creates a dead job.

## Why This Happened

Story 6.1's AC only validates the **front-end form + immediate response**, not the **end-to-end pipeline**. The form submission endpoint (`/api/ingest/file`, `/api/ingest/text`, `/api/ingest/url`) successfully:
- Receives the form data
- Creates a database record in the `job` table with status='New'
- Returns a JSON response with `jobId`

But there's no Story 4.1 (Overnight Batch Processing) handler that actually:
- Polls for `job.status='New'` entries
- Runs ingestion/sanitization/classification on the submitted content
- Updates the job status to 'Done' or 'Failed'

So from the user's perspective: they submit a form, get a Job ID, and then nothing happens.

## Root Cause

The AC was written to pass on **form functionality**, not on **pipeline functionality**. Story 6.1 and Story 4.1 are written as separate, independent stories. But the real-world acceptance should be: *"User submits form → pipeline processes submission → status visible to user."*

## Correction Approach

**Option A (Recommended):** Clarify Story 6.1 AC to be honest about scope
- Keep the current AC as-is (forms + Job ID)
- Add a note: "Note: This story creates jobs but does not process them. Story 4.1 (Overnight Batch Processing) consumes these jobs."
- Move Story 6.1 to **"Completed (API layer working; batch processing in Story 4.1)"**
- Do NOT call it "Working" (the work is done)

**Option B:** Expand Story 6.1 scope to include minimal batch processing
- Rewrite Story 6.1 to include a minimal batch handler that processes new jobs
- Takes longer, changes scope mid-story
- But gives end-to-end validation

**Option C:** Create a new acceptance story
- Story 6.1 stays as "Completed (form layer only)"
- Create Story 6.1.1 or Story 4.1.1: "End-to-End Pipeline Validation" — forms + batch processing
- Tests the full pipeline together

## Recommended Fix (Option A)

1. **Update Story 6.1 AC** to clarify scope:
   ```
   Acceptance Criteria:
   • Submitting form content creates a valid pipeline job and returns a unique Job ID immediately. ✅ (Form + immediate response working)
   • Note: Job processing (status updates, ingestion) is handled by Story 4.1 (Overnight Batch Processing), not this story.
   ```

2. **Change status** from "Completed" back to "Completed" (it IS complete for its scope) — OR use a new status like "Completed (API layer; batch in Story 4.1)" if the project uses that pattern.

3. **Add a dependency note** in Story 4.1: "depends on Story 6.1 (jobs table schema) and Story 6.3 (status dashboard to show results)."

4. **Create Story 8.4** (optional): "End-to-End Ingestion Pipeline Test" — manually submit form → wait for batch → verify job status + output in vault.
