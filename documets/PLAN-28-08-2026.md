## Step 1 — Story 12.2: Schema Redesign (EP12)

**Story text** (inserted into `documets/design/Project 4thBrain.md` under EP12):

> ### **Story 12.2: Schema Redesign**
>
> * **Abstract:** Schema redesign — continuation of Story 12.1.
> * **Description:** Continuation of Story 12.1 (Document/Status/Classification/Job Database Schema Design). Corrects `documets/design/schema.sql` and re-baselines `documets/design/classes.md` against what the schema actually implements today — Document, Status, Classification, Job, JobType, Tag (six entities), dropping `Process`/`JobDocument` which were added to `classes.md` after Story 12.1 shipped without a Story or ADR behind them (see Bug 1). Fixes outstanding syntax defects (`INTEGERPRIMARY KEY`, `DEFAUL` typo), broken index references (`status_id`/`topic_id` columns that don't exist), FK type mismatches (`TEXT` referencing `INTEGER` primary keys), and gives `tag` a real primary key (`name`) with a `document_tag` link table, since tags must be end-dated rather than deleted.
> * **Acceptance Criteria:**
>   * `schema.sql` executes via `db.exec()` against a fresh database file with no errors.
>   * Every index references a column that actually exists on its table.
>   * Every FK column's declared type matches the type of the primary key it references.
>   * `tag.name` is the primary key; `document_tag` links `document` and `tag`; deleting a tag sets `end_date` rather than removing the row.
>   * `job.document_id` references the document a job is processing (replacing the removed `job_document` link table).
>   * `job.status` references a new `job_status` lookup table (mirroring `status`), closing the previously-unconstrained free-text status field.
>   * `classification` is name-keyed (`name TEXT PRIMARY KEY`, no surrogate id); names are globally unique across the whole tree; `document.topic` references `classification(name)`.
>   * `job_file` tracks files associated with a job (name, path, mime_type, directory), FK'd to `job(id)`; its `status` column is intentionally unvalidated free text; `lock_by_PID` records the OS process ID holding the file locked, if any.
>   * `classification` is seeded with system directory roles (`VAULT_DIR`, `VAULT_RAW`, `VAULT_INCOMMING`, `DOCUMENT_ROOT`, `TMP_DIR`), each resolvable to an actual filesystem path via a matching uppercase key in `params.json`.
>   * `classes.md` lists exactly the entities present in `schema.sql`, with no reconciliation gaps noted.
> * **Dependencies:** none (continuation of Story 12.1)
> * **Status:** Approved for implementation planning

**Corrected version:**

```sql
-- SQLite schema for 4thBrain metadata storage
-- Source: documets/design/classes.md + Story 12.2 (Schema Redesign, closes Bug 1)
-- Date: 2026-08-28
-- Natural keys (name) on lookup tables (status, job_type, tag); no UUIDs/generated surrogate keys.
-- Timestamps stored as ISO-8601 UTC text; all FKs indexed.

CREATE TABLE status (
  name TEXT NOT NULL PRIMARY KEY,
  description TEXT
);

CREATE TABLE job_type (
  name TEXT NOT NULL PRIMARY KEY,
  description TEXT
);

CREATE TABLE classification (
  name TEXT NOT NULL PRIMARY KEY,
  parent TEXT REFERENCES classification(name)
);

CREATE TABLE document (
  id INTEGER PRIMARY KEY,
  name TEXT NOT NULL,
  uri_location TEXT NOT NULL,
  mime_type TEXT,
  charset TEXT,
  status TEXT NOT NULL REFERENCES status(name),
  created TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%fZ', 'now')),
  updated TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%fZ', 'now')),
  topic TEXT REFERENCES classification(name)
);

CREATE TABLE tag (
  name TEXT NOT NULL PRIMARY KEY,
  start_date TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%fZ', 'now')),
  end_date TEXT DEFAULT NULL,
  active BOOLEAN NOT NULL DEFAULT TRUE
);

CREATE TABLE document_tag (
  document_id INTEGER NOT NULL REFERENCES document(id),
  tag_name TEXT NOT NULL REFERENCES tag(name),
  PRIMARY KEY (document_id, tag_name)
);

CREATE TABLE job_status (
  name TEXT NOT NULL PRIMARY KEY,
  description TEXT
);

CREATE TABLE job (
  id INTEGER PRIMARY KEY,
  job_type TEXT NOT NULL REFERENCES job_type(name),
  document_id INTEGER REFERENCES document(id),
  start_date TEXT,
  end_date TEXT,
  status TEXT NOT NULL REFERENCES job_status(name),
  parent_job_id INTEGER REFERENCES job(id)
);

CREATE TABLE job_file (
  id INTEGER PRIMARY KEY,
  name TEXT NOT NULL,
  path TEXT NOT NULL,
  mime_type TEXT,
  directory TEXT,
  job_id INTEGER REFERENCES job(id),
  status TEXT, -- file status, not job status; not validated for now
  lock_by_PID INTEGER
);

CREATE INDEX idx_document_status ON document(status);
CREATE INDEX idx_document_topic ON document(topic);
CREATE INDEX idx_classification_parent ON classification(parent);
CREATE INDEX idx_document_tag_tag ON document_tag(tag_name);
CREATE INDEX idx_job_type ON job(job_type);
CREATE INDEX idx_job_status ON job(status);
CREATE INDEX idx_job_document ON job(document_id);
CREATE INDEX idx_job_parent ON job(parent_job_id);
CREATE INDEX idx_job_file_job ON job_file(job_id);

INSERT INTO status (name, description) VALUES
  ('New', 'Document captured but not yet processed.'),
  ('Processing', 'Document is being sanitized, transcoded, or classified.'),
  ('Indexed', 'Document has been filed into the vault and indexed for search.'),
  ('Failed', 'Processing failed and requires attention.'),
  ('Archived', 'Document processing complete and no longer active.');

INSERT INTO job_status (name, description) VALUES
  ('New', 'Job created but not yet started.'),
  ('Running', 'Job is actively executing.'),
  ('Completed', 'Job finished successfully.'),
  ('Failed', 'Job execution failed and requires attention.');

  ('convert', 'convert document to text'),
  ('classify', 'classify document'),
  ('index', 'index document');

  ('VAULT_DIR', null),
  ('VAULT_RAW', 'VAULT_DIR'),
  ('VAULT_INCOMMING', 'VAULT_DIR'),
  ('DOCUMENT_ROOT', 'VAULT_DIR'),
  ('TMP_DIR', null);
```

**Change-by-change summary:**
- `status.name`, `job_type.name`, `tag.name` → explicit `PRIMARY KEY`. No surrogate IDs anywhere in lookup tables.
- Fixed `id INTEGERPRIMARY KEY` → `id INTEGER PRIMARY KEY` (document) — missing-space syntax error.
- Fixed `DEFAUL` → `DEFAULT` typo (tag.end_date).
- `classification.parent_id`, `job.parent_job_id`: `TEXT` → `INTEGER` — were type-mismatched against the `INTEGER` PKs they reference.
- `job.job_type_id` renamed `job.job_type`, now `REFERENCES job_type(name)` (was referencing a nonexistent `job_type.id`).
- **New:** `job.document_id INTEGER REFERENCES document(id)` — restores the job→document link lost when `job_document` was removed.
- **New:** `document_tag` junction table (composite PK `document_id, tag_name`) — needed for the tag↔document link per the tag decision (name-keyed, soft-deleted via `end_date`).
- **New:** `job_status` lookup table (mirrors `status`, seeded New/Running/Completed/Failed) — `job.status` previously had no `REFERENCES` clause at all (unconstrained free text), unlike `document.status`. Closes that gap.
- **Reverted to name-keyed:** `classification` drops its surrogate `id` entirely — `name TEXT NOT NULL PRIMARY KEY` is now the sole key, `parent_id INTEGER` renamed to `parent TEXT REFERENCES classification(name)`. Classification names must be **globally unique** across the whole tree (no per-parent scoping — the earlier `UNIQUE(name, parent_id)` index is removed). `document.topic` changes from `INTEGER REFERENCES classification(id)` to `TEXT REFERENCES classification(name)` to match.
- **New:** `job_file` table — tracks files associated with a job (name, path, mime_type, directory), FK'd to `job(id)`. `job_file.status` is deliberately plain `TEXT` with no `REFERENCES` — file status, distinct from job status, not validated for now. `job_file.lock_by_PID` records the OS process ID currently holding the file locked, if any.
- Fixed all broken index column references; added indexes for the two new columns and for `job.status`/`job_file.job_id`.

**`classes.md` update (not yet applied):** re-baseline to exactly eight entities — Document, Status, Classification, Job, JobType, JobStatus, JobFile, Tag. Formally add `Tag` (fields: `name` PK, `start_date`, `end_date`, `active`), `JobStatus` (fields: `name` PK, `description`, mirroring `Status`), and `JobFile` (fields: `id` PK, `name`, `path`, `mime_type`, `directory`, `jobId` FK, `status` — unvalidated free text, `lockByPID` — OS process ID holding the file locked, if any), plus a Document↔Tag many-to-many relationship, a Job→JobStatus reference, and a Job→JobFile one-to-many. Note `Classification` is name-keyed (no surrogate id) with globally unique names, self-referencing via `parent`. Remove `Process`/`JobDocument` from the class list (they're not in the schema after this correction) and remove the file's closing note flagging Tag as "unreconciled" — it's reconciled by this Story. Update `classes.mmd` to match (regenerating `classes.png` is a manual step, noted but not automated here).

**`classification` seed data (replaces the old `'top'/'AI'` demo rows):** seeds five system directory roles instead of topic-taxonomy examples — `VAULT_DIR` and `TMP_DIR` as roots, `VAULT_RAW`/`VAULT_INCOMMING`/`DOCUMENT_ROOT` as children of `VAULT_DIR`. These names are looked up directly as `params.json` keys (see below) — `classification` now doubles as the registry of known directory roles, not just document topics.

**`params.json` additions (not yet applied — planned only):**
```json
{
  "VAULT_DIR": "C:\\Users\\rsant\\desar\\Local Vault\\Local Vault",
  "VAULT_RAW": "C:\\Users\\rsant\\desar\\Local Vault\\Local Vault\\raw",
  "VAULT_INCOMMING": "C:\\Users\\rsant\\desar\\Local Vault\\Local Vault\\incoming",
  "DOCUMENT_ROOT": "C:\\Users\\rsant\\desar\\Local Vault\\Local Vault\\documents",
  "TMP_DIR": "C:\\Users\\rsant\\desar\\Local Vault\\TMP_DIR"
}
```
Keys are uppercase, matching `classification.name` values exactly (enables a direct `params[classificationName]` lookup pattern), deliberately inconsistent with the existing lowercase `vault_dir`/`raw_dir` keys, which stay as-is and are unrelated to this new set. `VAULT_DIR` duplicates the existing `vault_dir` value; `VAULT_RAW`/`VAULT_INCOMMING` derive from it per ADR14. `DOCUMENT_ROOT` (`vault_dir + "\documents"`) and `TMP_DIR` (sibling to `raw_dir`, outside the vault) are new — not covered by any existing ADR, flagged for your review.

## Step 2 — Story 13.3: API (EP13, depends on Story 12.2) — planned, not yet created

**Draft story text (not yet inserted):**

> ### **Story 13.3: Unified Data-Access API**
>
> * **Abstract:** Replace ad-hoc SQL with a validated repository layer and per-table REST API.
> * **Description:** Continuation of Story 13.1 (Database Inspector — Table Browser & Admin Panel) and Story 6.1 (Web Ingestion Form & Submission Handler). Replaces `admin-db.js`'s generic, unvalidated PRAGMA-reflected CRUD engine and `ingest-service.js`'s raw `db.prepare()` calls with a shared repository layer (explicit per-table validation and business rules) and a thin REST API at `/api/tables/*`, documented via an OpenAPI spec and exposed through a Scalar interactive docs UI at `/api/docs`.
> * **Acceptance Criteria:**
>   * `server/lib/repositories/` exposes validated `list/get/create/update/remove` per table; "removing" a tag sets `end_date` rather than deleting the row.
>   * `/api/tables/*` REST routes contain no SQL or validation logic — they only call the repository layer.
>   * `ingest-service.js` contains no direct `db.prepare()` calls; it calls the repository layer instead, and no longer self-generates surrogate keys (uses SQLite's `lastInsertRowid`).
>   * `/api/docs` serves an interactive Scalar UI listing every `/api/tables/*` endpoint.
>   * Both `/api/tables/*` and `/api/docs` stay behind the existing `NODE_ENV=development` gate (extracted into reusable `server/middleware/dev-only.js`).
>   * `tagRepository`, `statusRepository`, and `jobTypeRepository`'s `update()` reject changes to the `name` column (the primary key) — renaming means end-dating the old row and inserting a new one, not an in-place `UPDATE`.
> * **Dependencies:** depends on Story 12.2 (corrected schema), depends on Story 6.4, depends on Story 13.1, depends on Story 6.1
> * **Status:** Proposed — pending creation

### Repository layer (`server/lib/repositories/`)

One file per table (`status.js`, `jobType.js`, `classification.js`, `document.js`, `tag.js`, `documentTag.js`, `job.js`), each exporting `list/get/create/update/remove` with domain validation. Representative examples:
- **`tag.js`** — `remove(name)` sets `end_date = now, active = false` instead of `DELETE`.
- **`document.js`** — `create()` validates `status` against the `status` table's allowed values; omits `id` from the INSERT, reads back `lastInsertRowid`.
- **`job.js`** — `create()` validates `jobType` against `job_type`, requires `documentId` to reference an existing document.

Natural-keyed tables (`tag`, `status`, `job_type`) treat their `name` column as immutable once created — no repository exposes an in-place rename. `update()` on these tables only touches non-key columns (e.g. `description`, `active`); changing the identity itself means retiring the old row (`tag`: set `end_date`) and inserting a new one.

### `ingest-service.js` rewrite

Becomes a thin orchestrator calling the repository layer instead of raw SQL: `documentRepository.create(...)`, `tagRepository.upsert(name)`, `documentTagRepository.link(documentId, tagName)`, `jobRepository.create({ jobType: 'ingest', documentId, status: 'New' })`. No more app-generated IDs; no more `job_document` insert (removed — `job` now carries `document_id` directly).

### REST layer (`server/routes/api/`)

One thin router per table, translating HTTP verbs to repository calls — no SQL, no validation. Mounted under `/api/tables/<table-name>`, behind `server/middleware/dev-only.js` (extracted from `admin-db.js`'s inline gate). Delete `server/routes/admin-db.js` entirely (superseded by this layer + Step 3's admin page).

### OpenAPI + Scalar (D3/D7)

Add `@scalar/express-api-reference` to `server/package.json`. New `server/openapi/spec.js`: OpenAPI 3.0 document, one path group per table, schemas matching the corrected `schema.sql`. Mount at `GET /api/docs`, same dev-only gate.
