# Document Ingestion Pipeline — Implementation Plan

## Context

`documets/Process.md` describes a 6-actuator ingestion pipeline (Input Handler, Web Clipper, Content Extraction, Vector Embedding, Semantic Classifier, Vault Persistence). Investigating the codebase to plan its implementation surfaced that the project already has a **more detailed, authoritative design** for this exact pipeline — `documets/design/Ingestion-State-Diagram.md`, `documets/story/story-6.1.md` (exact actuator specs: Clipper, Extractor, RAG Indexing, Classification), and ADR3/4/6/10/14/15/17 — which this plan follows instead of Process.md's simplified model, per two decisions confirmed with the user:

1. **RAG Indexing, not direct Ollama embedding.** ADR3/ADR4 establish that Smart Connections (the Obsidian plugin) generates embeddings automatically once a file lands in the vault — there is no direct Ollama embedding call. "Vector Embedding" in Process.md becomes "RAG Indexing": copy file to vault, poll Smart Connections for success/fail/too-short.
2. **Mock Clipper; Extractor is real for archives, mocked for everything else.** `spike-webclipping.md` (real URL-fetch tool choice) is unresolved, so Clipper stays mocked (SUB-TASK-6.1.1) this pass. `spike-extraction.md` is partially resolved by user direction: the Extractor gets a **real** implementation this phase, scoped to compressed/archive formats only — `.zip`, `.tar`, `.Z` — since those need only decompression, not OCR/document parsing. Extraction of PDFs, images, and Office documents remains mocked (SUB-TASK-6.1.2) until a later phase picks an OCR/parsing library. The real Extractor's output is different in kind from before: instead of one seeded transcription, it unpacks N member files and **submits each as a new document back through `ingest`**, so each extracted file gets routed by its own type (text, another archive, or — later — another binary) rather than being assumed to be indexable text.

While verifying the design, I found the actual blocker: **the repository layer is broken against the current schema**, not just the known status-casing bug. `server/lib/repositories/document.js` and `job.js` reference columns (`created_date`, `ingestion_notes`) that don't exist in `documets/design/schema.sql` post-Story-12.2; `tag.js`/`classification.js` reference a `description` column neither table has. This means **no document or job can currently be created without throwing** — confirmed by reading the files directly. Fixing this is Phase 0, a prerequisite for everything else, not new design work (it's conforming code to the already-approved `schema.sql`).

**Schema addition (user-directed):** `document` gets two new columns — `parent INTEGER REFERENCES document(id)` and `author TEXT`. Whenever an actuator's output is a genuinely new file (not a relocation of the same content), it creates a **new** `document` row for that output with `parent` set to the input document's id and `author` set to the actuator's name, instead of mutating the input row in place. This resolves a gap the Extractor handler would otherwise hit: previously there was no FK to link a transcription back to its source binary, so the plan had to fake a back-reference through a `job_file` audit row. Applies to:
- **Clipper** (mock, Phase 2): fetched content → new document, `parent = URL document.id`, `author = 'Clipper'`. Embedded image references found in that fetched content → new child documents, `parent = the fetched-content document's id` (not the original URL document — the images are referenced by the fetched page, not by the raw URL entry), `author = 'Clipper'`.
- **Extractor** (mock and real, Phase 2): output document(s) → `parent = binary/archive document.id`, `author = 'Extractor'`. The binary/archive document itself is archived (`status → 'Archived'`) once its original file is copied to `VAULT_RAW` — it stops being an active pipeline row; the pipeline continues on the new child document(s).
- **RAG Indexing and Classification** relocate/rewrite the *same* file's location (vault copy, then final filing) rather than deriving new content — no new document row, no `parent`/`author` set, same document continues through `index`→`classify`.
- The root document created at ingestion (form/API submission) has `parent = NULL`, `author = NULL` — it's the entry point, not an actuator's output.

No job queue processor exists yet — jobs created by Story 6.1's form sit dead (`documets/6.1-pipeline-gap.md`). This plan's Phase 1 builds that processor; Phases 2–3 give it real (or story-appropriately-mocked) work to do; Phase 4 validates the 13 acceptance-criteria cases already listed in `story-6.1.md`.

**Reusable pieces confirmed to exist and build on, not duplicate:**
- `server/lib/repositories/*.js` + `tx.js` (`withTransaction`) + `errors.js` (`ValidationError`/`NotFoundError`) + `helpers.js` (`assertExists`) — the data-access layer.
- `server/lib/raw-dir-writer.js` — writes uploads into `RAW_DIR/inbox` or `/clipping`.
- `server/lib/smart-connections-status.js` — already has `lookup(config, notePath)`, which parses `.smart-env/smart_sources/smart_sources.ajson` and returns `{status: current|missing|skipped|unexpected, reason}`. This is exactly what RAG Indexing needs to poll — reuse directly.
- `openai` npm package (already installed, currently unused) — the intended Ollama client per ADR6, pointed at `config.ollamaBaseUrl`.
- `server/config.js` (`buildConfig()`) / `params.json` — extend, don't replace.
- `mime-types` (already installed) — used to type each file extracted from an archive.

**New dependencies (Phase 2, real Extractor):**
- `adm-zip` — ZIP extraction, synchronous API, fits the codebase's existing synchronous `node:sqlite` style.
- `tar` — TAR extraction (official npm package, streaming/async, strips `..`/absolute paths by default).
- `.Z` (Unix `compress`/LZW) has no maintained pure-JS decompressor. Plan: attempt via a system `uncompress` binary on `PATH` if present, else fail that document gracefully (`Failed`, routed to `VAULT_RAW`, reason logged) rather than block the phase on finding/vetting an obscure library. Flagged below as a scoped caveat, not a blocking Design Debt — `.zip`/`.tar` are the two formats actually likely to be exercised.

## Phase 1 — Job Queue Processor (Story 4.1)

**Architecture: in-process `setInterval` inside `server/index.js`**, not a separate script — ADR5 designates Node.js as the single orchestration layer; a separate process would be a second SQLite lock-holder against ADR17's brief-transaction concern. This corrects `story-4.1-plan.md`'s PowerShell sketch to fit the actual stack (Design Debt #6 covers the artifact's location, not its content).

**`job_type` → actuator mapping** (only 4 seeded types exist: `ingest, convert, classify, index`):

| job_type | Actuator | On success, enqueues |
|---|---|---|
| `ingest` | Intake triage + Clipper (URL-origin docs only) | `convert` (binary) or `index` (text) |
| `convert` | Extractor | `index` |
| `index` | RAG Indexing | `classify` |
| `classify` | Classification | *(terminal)* |

Each handler enqueues the next stage as a new `job` row with `parent_job_id` set to itself, using `repos.job.createChild`.

**`document.status` lifecycle** (derived from the seeded status *descriptions*, which only make sense in one order): `New` → `Processing` (set on `ingest` start; covers all three middle stages) → `Indexed` (set only after Phase 3's real vault filing — the seed description literally says "filed into the vault") → `Failed` (any stage's terminal failure).

### Logging (leveled, app-wide, ID-bound errors)

**`server/lib/logger.js`** — extends ADR11 (structured JSON to stdout) with real levels:

```js
const LEVELS = { info: 0, warning: 1, error: 2 };  // DEBUG/TRACE not needed for now — 3 levels only

function createLogger(configuredLevel) {
  const threshold = LEVELS[configuredLevel] ?? LEVELS.info;
  function emit(level, event, message, fields) {
    if (LEVELS[level] < threshold) return;
    console.log(JSON.stringify({ ts: new Date().toISOString(), level, event, message, ...fields }));
  }
  const base = {
    info:    (event, message, fields) => emit("info", event, message, fields),
    warning: (event, message, fields) => emit("warning", event, message, fields),
    error:   (event, message, fields) => emit("error", event, message, fields),
  };
  // Binds documentId/jobId so every call site in a handler carries them automatically —
  // structural guarantee instead of a "remember to pass the id" convention.
  base.forDocument = (documentId, jobId = null) => {
    const bound = {};
    for (const lvl of Object.keys(LEVELS)) {
      bound[lvl] = (event, message, fields = {}) => emit(lvl, event, message, { documentId, jobId, ...fields });
    }
    return bound;
  };
  return base;
}

module.exports = { createLogger, LEVELS };
```

**`params.json`**: add `"log_level": "info"` — one setting for the whole application (not per-module), read once at startup (not hot-reloaded).
**`server/config.js`**: add `logLevel: (params.log_level || "info").toLowerCase()`.
**`server/index.js`**: `const logger = createLogger(config.logLevel);` once, near the top, passed into everything that logs (the poller, the repositories' callers, route handlers as needed).

**Standard start/end INFO log — centralized in the poller, not duplicated per handler.** Every actuator run gets a uniform entry log and exit log, each showing `{id, name, status}` for the document — emitted once by the poller wrapping the handler dispatch, so no individual handler file needs to remember to add it:
```js
// inside pollOnce()'s per-job loop, server/lib/job-queue/poller.js
const document = repos.document.get(job.document_id);
const log = logger.forDocument(document.id, job.id);
log.info("actuator_start", `${job.job_type} starting for document ${document.id} ("${document.name}"), status=${document.status}`,
  { id: document.id, name: document.name, status: document.status });

repos.job.markRunning(job.id);
try {
  await handlers[job.job_type]({ job, document, repos, cfg, logger });
  repos.job.markCompleted(job.id);
  const after = repos.document.get(document.id);
  log.info("actuator_end", `${job.job_type} completed for document ${after.id} ("${after.name}"), status=${after.status}`,
    { id: after.id, name: after.name, status: after.status });
} catch (err) {
  repos.job.markFailed(job.id);
  const after = repos.document.get(document.id);
  log.error("actuator_end", `${job.job_type} failed for document ${after.id} ("${after.name}"), status=${after.status}: ${err.message}`,
    { id: after.id, name: after.name, status: after.status });
}
```
The document is re-fetched after the handler runs so the "end" log reflects its actual post-handler status (e.g. `Processing → Archived` for Extractor, `Processing → Failed` for a failed RAG-index) rather than repeating the stale pre-handler value.

**Handler-level logging stays narrow:** since the poller already provides the uniform start/end audit trail, individual handler files (`ingest.js`, `convert.js`, `index.js`, `classify.js`) only log their own domain-specific WARNING/ERROR cases — they don't add their own generic start/end lines. Bind a document-scoped logger inside the handler only when it needs to log something beyond the poller's wrapper, e.g.:
```js
const log = logger.forDocument(document.id, job.id);
log.error("zip_extract_failed", `ZIP extraction failed for document ${document.id} ("${document.name}"): entry "${entry.entryName}" resolves outside the extraction target — rejected as a zip-slip attempt`, { entryName: entry.entryName });
```

**Level guidance** (ERROR usage is self-evident — failures; WARNING is what needs judgment):

| Level | Use for | Example |
|---|---|---|
| ERROR | Terminal failure of a job/document/operation | `ZIP extraction failed for document 42 ("notes.zip"): unexpected end of archive at offset 8192` |
| WARNING | Degraded-but-continuing situations — validation caught something odd but processing continues | `Document 42: zip entry "../../etc/passwd" rejected (zip-slip); continuing with remaining 11 entries`; `Document 17 ("notes.md") sampled as binary-looking (2 blocks, NUL byte at offset 340) — RAG Indexing expects text; continuing, Smart Connections may skip/fail it` |
| INFO | The poller's standard start/end audit trail (see above); other normal lifecycle events as needed | `ingest starting for document 42 ("report.pdf"), status=New` / `ingest completed for document 42 ("report.pdf"), status=Processing` |

Every ERROR call site must include a document/file id in its bound fields (via `forDocument`, or an explicit `documentId` field for errors that aren't handler-scoped, e.g. startup failures) and a message specific enough to act on without re-reading the code — name the operation, the input, and the concrete cause (not `"extraction failed"`, but *why* and *which entry/file*).

**Files to create:**
- `server/lib/job-queue/poller.js` — `startJobQueuePoller({db, repos, config, handlers, logger})`: `setInterval` at `config.jobPollIntervalMs` with a `running` reentrancy guard (critical: `setInterval` doesn't wait for async callbacks — without the guard, a slow tick could overlap the next one and double-process a job); `pollOnce()` does `repos.job.listNew(config.threadCount)` then processes **sequentially** (`for...of`, not `Promise.all`) — this single choice satisfies both ADR10 (concurrency=1 for Ollama) and ADR17 (brief transactions) without extra logic, regardless of job type mix. Per job: the start/end INFO wrapper above, `markRunning` → dispatch to `handlers[job.job_type]` → `markCompleted`/`markFailed`. DB transactions wrap only metadata writes, never the actual I/O (file copy, HTTP fetch, LLM call, Smart Connections poll).
- `server/lib/job-queue/handlers.js` — **Phase 1 ships stub handlers for all 4 types** (`throw new Error('job_type "<type>" handler not yet implemented')`), per the user's build-one-story-at-a-time preference. This proves the New→Running→Failed plumbing, timestamps, reentrancy guard, and the start/end logging with id/name/status all work correctly before any actuator logic exists.

**`server/config.js`**: add `threadCount: params.thread_count ?? 1`, `jobPollIntervalMs: params.job_poll_interval_ms ?? 5000`, `logLevel` (above).
**`params.json`**: add `"thread_count": 1`, `"job_poll_interval_ms": 5000`, `"log_level": "info"`.
**`server/index.js`**: after `app.locals.repositories = createRepositories(db)`, create the logger and start the poller with `app.locals.db`/`app.locals.repositories`/`config`/the stub `handlers` module/`logger`.

Check stdout for `actuator_start` and `actuator_end` JSON lines — both showing `id`/`name`/`status`, the end line at `level:"error"` naming the job type and the "not yet implemented" cause. ## Phase 2 — Mock Clipper/Extractor + real RAG Indexing (Stories 1.1/1.2/3.1)

**Directory mapping:** `TMP_DIR` (from `Ingestion-State-Diagram.md`/`schema.sql`'s seed) ≈ `$RAW_DIR` (ADR14's actual staging dir) — `raw-dir-writer.js` already writes there. Add `cfg.tmpDir = cfg.rawDirInbox` alias; add `cfg.vaultIncomingDir`/`cfg.vaultRawDir` (`path.join(vaultDir, "incoming"|"raw")`, `ensureDir()`'d same as today's raw dirs).

**`server/lib/job-queue/fixtures.js`** — seeded mock constants per SUB-TASK-6.1.1/6.1.2 (`MOCK_HTML_WITH_IMAGES` with 2 `<img>` refs, `MOCK_MARKDOWN`, `MOCK_PDF_URL_TEXT`, `MOCK_ZIP_LISTING`, `MOCK_PDF_EXTRACTED_TEXT`, `MOCK_OCR_TEXT`, `MOCK_DOCX_EXTRACTED_TEXT`, `MOCK_GENERIC_TRANSCRIPTION_NOTE`).

**`server/lib/job-queue/handlers/ingest.js`** (`job_type=ingest`): `updateStatus('Processing')` on the input document. If URL-origin (`uri_location` under `rawDirClipping`): mock Clipper — pick seeded content by URL extension (`.pdf`/`.zip`/`.md`/else→HTML-with-images), write to `tmpDir/{id}.{ext}`, then `repos.document.create({..., parent: inputDocument.id, author: 'Clipper', status: 'New', ...})` for the fetched content itself; for the HTML-with-images case, create one further child document per mocked `<img>` ref with `parent = ` the fetched-content document's id (not the URL document), `author: 'Clipper'`. `job_file` audit row on the input document. Enqueue `index` against the **new fetched-content document**, not the input URL document (all 4 mock outputs are text-form per the SUB-TASK spec, even the PDF-URL case). Otherwise (non-URL input) inspect `mime_type`: `text/*` → enqueue `index` directly against the input document itself (Story 1.1, no new document — it's already the right content); else → enqueue `convert` against the input document (Story 1.2).

**`server/lib/job-queue/handlers/convert.js`** (`job_type=convert`) — branches by extension into two paths:

**Path A — real Extractor, archive formats only (`.zip`, `.tar`, `.Z`):**
1. `server/lib/job-queue/extractors/archive.js` — `extractArchive(filePath, ext, targetDir)`:
   - `.zip` (`adm-zip`): open, then for each entry **validate before writing** — resolve `path.join(targetDir, entry.entryName)`, reject/skip the entry if the resolved path doesn't stay under `targetDir` (zip-slip protection; `adm-zip`'s own `extractAllTo` doesn't fully guard this on its own) — then write. Skip directory entries.
   - `.tar` (`tar` package): `tar.extract({file: filePath, cwd: targetDir})` — the `tar` package already strips `..`/absolute paths by default, but confirm `preservePaths: false` is explicit rather than relied on implicitly.
   - `.Z`: single-file decompress (Unix `compress` is not a multi-file container like zip/tar) via `child_process.execFile('uncompress', ...)` if found on `PATH`; if not found, throw a clear "no decompressor available" error.
   - Returns a list of `{relativePath, absolutePath, sizeBytes}` for every extracted file (recursive walk of `targetDir` for zip/tar; the single output file for `.Z`).
2. In the handler: `updateStatus('Processing')` on the archive document (already set by `ingest`, kept explicit here). Extract into `tmpDir/{archiveDocument.id}_extracted/`.
3. If extraction throws, or the archive yields zero files: copy the original archive to `vaultRawDir`, `updateStatus('Failed')`, `job_file` audit row with the failure reason, rethrow (job → `Failed`). This covers corrupt archives, empty archives, and the `.Z`-with-no-decompressor case.
4. On success, for **each** extracted file: move it into `tmpDir/{newId}__{sanitizedBaseName}` (flat, unique-named — nested archive directory structure isn't preserved on disk, only in `document.name`), detect `mimeType` via `mime-types` from the extension, `repos.document.create({name: relativePath, uriLocation: newPath, mimeType, status: 'New', parent: archiveDocument.id, author: 'Extractor'})`, then `repos.job.createChild('ingest', newDocument.id, currentJobId)` — **submitted back to the ingestor, not directly to `index`**, so each extracted file is routed by its own actual type. A nested archive extracted from this one will naturally re-enter this same `convert` path on its own subsequent `ingest`→`convert` cycle — no special-casing needed, though note this has no recursion-depth or zip-bomb guard in this pass (acceptable given ADR18's low-volume, single-user context; flag as a future hardening item, not solved now).
5. Copy the original archive file to `vaultRawDir` (ADR14 archival), `updateStatus('Archived')` on the archive document (its N children carry the pipeline forward independently). `job_file` rows: one per extracted file plus one for the archived original.
6. This handler does **not** enqueue `index` itself — the N child `ingest` jobs each decide their own next step.

**Path B — mock Extractor, everything else (PDF/image/DOCX/other, SUB-TASK-6.1.2):** unchanged from the original mock design — pick seeded text by mime type, write to `tmpDir/{id}_transcription.txt`, `repos.document.create({name: ..., uriLocation: transcriptionPath, mimeType: 'text/plain', status: 'New', parent: binaryDocument.id, author: 'Extractor'})`, copy original to `vaultRawDir`, `updateStatus('Archived')` on the binary document, `job_file` row, then enqueue `index` directly against the new transcription document (mocked content is already known-good text, no need to round-trip through `ingest`).

**`server/lib/job-queue/handlers/index.js`** (`job_type=index`, **real** RAG Indexing):
1. **Text-sniff pre-check (non-blocking, WARNING only):** `server/lib/job-queue/text-sniff.js` — `looksBinary(filePath)` reads a small sample (2 blocks of 4096 bytes = first 8KB) via `fs.readSync` on an open fd and checks for a `NUL` byte or a high ratio (>30%) of non-printable control bytes in the sample. RAG Indexing is specified to receive only text (`Ingestion-State-Diagram.md`'s `CheckType` split already routed binaries to Extractor before this point), so this is a **sanity check on an assumption**, not new validation logic — if it trips, `log.warning('index_binary_content_detected', ...)` with the document id and the specific trigger (NUL byte offset, or the non-printable ratio found), then **continue processing anyway** — it doesn't block the copy or change `document.status`; Smart Connections' own `lookup()` result a few steps later is still the real success/fail arbiter. This only exists to surface a same-cause-earlier signal in the logs before Smart Connections' skip/fail shows up.
2. Copy `tmpDir` file → `vaultIncomingDir/{id}.md`; `job_file` audit row; **poll** `smart-connections-status.js`'s `lookup(cfg, 'incoming/' + id + '.md')` every `smartConnectionsPollIntervalMs` up to `smartConnectionsPollTimeoutMs` (new `params.json` keys, defaults 3000/60000ms) since Smart Connections embeds asynchronously outside this process. `current` → enqueue `classify`. `skipped` with a "Below minimum size" reason → move to `VAULT_NOTES` (blocked on Design Debt #7 sign-off), `updateStatus('Failed')`, `log.error('index_too_short', ...)` with the document id and char count. Any other `skipped`/`unexpected`/timeout → move to `vaultRawDir`, `updateStatus('Failed')`, `log.error('index_failed', ...)` with the document id and Smart Connections' own `reason` string. *(Accepted tradeoff: this poll-wait runs inside the outer poller's sequential tick, so one document's wait blocks others behind it — acceptable given ADR18's stated low volume; not solved in this pass.)*

**Verification:** typed text → `ingest`→`index` chain completes on the same document (`parent`/`author` stay NULL), `classify` job created (Phase-1-stub-Failed, expected). `.pdf`-named local file → `ingest`→`convert` (mock path) creates a child transcription document (`parent=`binary doc id, `author='Extractor'`; binary doc itself now `status='Archived'`) → `index` runs against the child. URL ending `.md` → mock Clipper creates a child document (`author='Clipper'`) → `index` against that child. Plain HTML URL → Clipper's fetched-content child document plus 2 grandchild `document` rows for mocked images (`parent` = the fetched-content document, not the URL document). Submit a document whose content is actually binary (e.g. rename a small image to `.txt` and ingest it as typed text's mime-type override) → confirm an `index_binary_content_detected` WARNING line appears with the document id and trigger reason, but the job still proceeds to poll Smart Connections rather than failing outright — confirms the sniff check is diagnostic-only, not a gate.

**Archive-specific verification:** submit a real local `.zip` containing 2 text files and 1 nested `.tar` → confirm `ingest`→`convert` (real path) extracts to `tmpDir/{id}_extracted/`, archive document → `status='Archived'`, 3 new child documents created (`author='Extractor'`, `parent`=archive doc id) each with its own new `ingest` job — the 2 text files proceed `ingest`→`index` on their own; the nested `.tar` proceeds `ingest`→`convert`→(2 more grandchildren)→`ingest`→`index` each. Confirm `document.parent` chains are correct end to end (`/admin/db`, filter by `author='Extractor'`). Submit a corrupt/truncated `.zip` → confirm `convert` job `Failed`, archive copied to `VAULT_RAW`, no child documents created. If a `.Z` sample is available, confirm either successful single-file extraction+re-ingest, or a clean `Failed`+`VAULT_RAW` routing with a logged "no decompressor" reason if `uncompress` isn't on `PATH`.

`job_file` rows exist for every file movement; filesystem matches at each stage.

## Phase 3 — Real Classification (Story 2.1)

**Frontmatter schema** (Design Debt #5 — resolved now as part of this phase's own design work, since Story 2.1's AC can't be met without picking field names regardless of when it happens):
```yaml
---
title: "{document.name}"
tags: [tag1, tag2, tag3]
topic: "{topic}"
subtopic: "{subtopic}"
source: "{original uri_location before mocking}"
created: "{document.created}"
original: "{relative path in VAULT_RAW, or null}"
---
```
`tags` are treated as open-vocabulary for this pass (no taxonomy-enforcement file exists anywhere in `documets/`, and `tag` isn't a fixed-enum table) — Story 2.1's "matches configured taxonomy" AC is flagged aspirational, not blocking.

**`server/lib/job-queue/handlers/classify.js`** (`job_type=classify`):
1. Read vault-incoming content. Call Ollama via `openai` SDK (`baseURL: cfg.ollamaBaseUrl, apiKey: "ollama"`, `client.chat.completions.create(...)`) with a system prompt requiring strict JSON `{topic, subtopic, tags: []}`. Naturally satisfies ADR10 (concurrency=1) since the poller is already sequential — no extra locking needed.
2. Defensive `JSON.parse` — on failure, `log.error('llm_parse_failed', \`Classification failed for document ${document.id} ("${document.name}"): Ollama returned non-JSON or malformed response — ${err.message}\`, {rawResponse})` via `logger.forDocument(document.id, job.id)`, throw (job → `Failed`, but `document.status` stays `Processing`, not `Failed` — content is safely indexed, just not yet classified, so it's retryable).
3. On success: `repos.classification.upsert(topic, 'VAULT_DIR')`, `upsert(subtopic, topic)`; `repos.tag.upsert(tagName)` + `document_tag.link(...)` per tag.
4. Write frontmatter + content to `path.join(vaultDir, topic, subtopic, sanitize(name) + '.md')` (ADR15's formula). Look up `repos.document.listChildren(document.id)` — any child documents (Clipper's mocked image refs, or the parent binary document if this is a transcription being filed) copy into a sibling `.../{name}/` dir. Remove the file from `vaultIncomingDir`.
5. `updateStatus('Indexed')` (terminal success — matches the seed description "filed into the vault and indexed for search"). `job_file` row (`directory:'VAULT_TREE', status:'Filed'`).

**Verification:** confirm Ollama reachable at startup. Re-run a Phase 2 document through to `classify` — `document.status='Indexed'`, `topic` set, filed `.md` has valid frontmatter matching the schema above. Check `/admin/db` → `classification`/`tag`/`document_tag` rows. Force a malformed-JSON case (bad model name) — confirm `llm_parse_failed` log, job `Failed`, document stays `Processing` (not corrupted). Watch Ollama's process while 2 jobs are queued — confirm only one call in flight at a time.
