# Story P1.18 — The Unified Composer

## Problem

P1.11, P1.17 and P1.13 each deliver a piece of "one entry point for everything the user puts into the
vault", and none of them lands the piece the user actually sees. P1.11 makes the pipeline callable.
P1.17 is a spike — its own scope forbids production code — and only produces a routing decision.
P1.13 makes `/api/ingest/capture` (text and URL) and `/api/ingest/file` work behind whatever front end
is already there, which today is still three separate panels (Add File, Add Text, Add URL) plus a
fourth for Chat.

The composer that makes those feel like one entry point does not exist yet. This story is that
follow-on, named as an exit criterion of P1.17's own acceptance criteria ("Follow-on story:
Implementation storied separately, blocked by P1.13").

## Change

1. Build the option P1.17's spike named as its routing decision (recorded as ADR27) into
   `index.html`: one composer — a text area, a row of buttons, `[+]` to attach a file — replacing the
   Add File, Add Text and Add URL panels. Chat's panel is untouched unless the spike's exit criteria
   said otherwise; see ADR27 for what was actually decided.
2. Wire the composer to the endpoints P1.13 built: a typed URL posts `{ "url": ... }` and a note posts
   `{ "text": ... }`, both to `POST /api/ingest/capture`; an attached file still posts multipart to
   `POST /api/ingest/file`. The composer's own URL-detection rule (written precisely by the spike) is
   what picks `url` vs `text` — the server does not re-derive it (ADR26).
3. Implement the URL rule exactly as the spike specified: trigger, timing, and any override the user
   has for forcing plain-text treatment of something that parses as a URL.
4. Carry over the spike's composition answers: text plus an attached file, several files at once,
   where tags live, whether the composer resets after each send.
5. Apply the response shape from ADR26 (`{ id, status, message }`) to update the receipt feed; build
   per-document status only if the spike's status-feed statement named this story as the owner.
6. Remove the three superseded panels and their now-dead JavaScript from `index.html` once the
   composer covers their function. Keep ADR25's constraints: the page stays in `templates/`, no
   bundler, no framework, and no `th:inline="javascript"` is added to any script block using template
   literals.

## Acceptance Criteria

- `index.html` presents one composer for file, text and URL capture; the three panels it replaces are
  gone, along with any JavaScript that only served them
- A typed URL, a typed note, and an attached file each reach the vault through the endpoint P1.13
  built for that input, with no client-side guess duplicated server-side
- The URL rule matches the spike's written specification, including its override
- The receipt feed reflects the response shape from ADR26 for every submission
- Manual smoke test: all three input types submitted through the composer against a running app, each
  visible moving through the pipeline

## Dependencies

Blocked by **P1.13** (the endpoint the composer calls must exist) and **P1.17** (the routing decision
and ADR27 this story implements). Cannot start until ADR27 is written.
