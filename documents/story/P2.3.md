# Story P2.3 — TextExtractor Real Logic

## Overview

TextExtractor converts documents (PDF, DOCX, PPTX, XLSX, HTML, EPub) into Markdown suitable for LLM consumption. Archives originals to raw vault area. Routes to Classifier.

## Important Note

**The extraction stack for this story will be determined by the outcome of P2.8 (MarkItDown spike).** The currently documented stack (Turndown, Mammoth, OpenDataLoader) is inherited from v03's Node.js implementation and cannot run in a Java/Spring Boot environment.

P2.8 will provide:
- A measured comparison of MarkItDown vs Apache Tika
- A recommendation for the chosen extraction approach
- Architecture Decision Record (ADR) documenting the choice

## Implementation Requirements

Pending P2.8 outcome. Likely approaches:

1. **MarkItDown via subprocess** — Call `markitdown` CLI via ProcessBuilder, with timeout and error handling
2. **Apache Tika** — Use Tika for text extraction and Flexmark for HTML-to-Markdown conversion
3. **HTTP sidecar** — Call a local FastAPI/Flask wrapper around MarkItDown

## Scope

- ZIP handling stays in Java per P1.8 (one-per-member model)
- Round-trip plain text/Markdown as-is; no reason to re-convert
- Image extraction out of scope (no OCR)
- Archive originals to vault before producing Markdown

## Acceptance Criteria

Pending P2.8 outcome. Will include:
- Multi-format support (PDF, DOCX, PPTX, XLSX, HTML, EPub)
- Quality assessment against LLM consumption requirements
- Timeout enforcement to prevent pipeline stalls
- Error handling for corrupt or unsupported files
