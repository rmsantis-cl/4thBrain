# Story P2.3 — TextExtractor Real Logic

## Overview

`Extractor` archives the original to the raw vault area, converts it to Markdown through the
`MarkdownConverter` seam, writes the Markdown, sets the Document's status, and routes to the
Classifier. It does not itself know how conversion happens.

## The stack, settled

Version 1.0 of this story named "PDF → OpenDataLoader, HTML → Turndown, Word → Mammoth". That list
was inherited from v03, which ran on Node.js. All three are JavaScript libraries and v04 has no Node
runtime, so the story specified work that could not be done.

**ADR28 settles it: MarkItDown, invoked as a subprocess, behind a `MarkdownConverter` interface.**
Story P2.9 builds the interface and the implementation. This story consumes them and adds no
knowledge of Python, `ProcessBuilder` or MarkItDown anywhere in `Extractor`.

Two things about that decision this story has to respect:

- It was taken on the argument, not on P2.8's corpus measurements, which have not been run. ADR28's
  triggers 1 and 2 (format census; share of scanned PDFs) can still reverse the stack. If they fire,
  the class behind the interface changes and **this story does not**, which is the point of the seam.
- On PDF, MarkItDown returns flat text with no heading structure. Do not write acceptance criteria
  for this story that assume Markdown headings come back from a PDF.

## Implementation Requirements

- Archive the original into the raw vault area, recording a `document_copy` row (P1.8), **before**
  conversion. A failed conversion must leave a re-runnable original behind.
- Call `MarkdownConverter.convert(path, extensionHint)`. Skip the call entirely for the passthrough
  formats the converter reports as unsupported — plain text and Markdown are stored as-is.
- Write the resulting Markdown to the vault with front matter carrying the converter name and
  version, taken from `MarkdownConverter.probe()` and cached once rather than probed per document.
- Set status and route to the Classifier on success.
- Handle `ConversionException` inside the actuator's loop, not around the thread body, so one bad
  document does not end the thread.

### Failure mapping — binding, from P2.9

This table is copied verbatim from Story P2.9 and is a contract between the two. Confirm the status
constants against the existing `Document` status values and add what is missing, along with a field
able to hold the reason detail.

| `ConversionException.Reason` | Status | Why |
|---|---|---|
| `UNSUPPORTED_FORMAT` | `EXTRACTION_UNSUPPORTED` | queryable backlog of formats to add a converter for |
| `EMPTY_RESULT` | `EXTRACTION_EMPTY` | the scanned-PDF case; queryable backlog for a later OCR story |
| `TIMEOUT`, `CONVERTER_FAILED`, `TOO_LARGE`, `OUTPUT_TOO_LARGE`, `IO_ERROR`, `UNAVAILABLE` | `EXTRACTION_FAILED` | retry candidates once a human has looked |

Three rules follow:

- No failure path leaves a document in an in-progress status. The terminal status and the reason
  detail are written in the same transaction, before the next queue item is taken.
- Nothing else in the pipeline moves a document out of `EXTRACTION_*` on its own. These are terminal
  until a retry command or an OCR story moves them deliberately.
- A document that fails conversion is never routed to the Classifier.

## Scope

- ZIP handling stays in Java per P1.8, one Document per member. The converter rejects `.zip` by
  design; `Extractor` never hands it one.
- Plain text and Markdown are stored as-is. No round trip through the converter.
- Image extraction and OCR are out of scope. A scanned page produces `EXTRACTION_EMPTY`.
- Building the converter is P2.9's, not this story's.

## Acceptance Criteria

- `Extractor` compiles against `MarkdownConverter` only. It contains no reference to
  `MarkItDownConverter`, `ProcessBuilder`, or any string containing "python" or "markitdown".
- A DOCX with two heading levels reaches the Classifier with Markdown containing `# ` and `## `.
- A digital-text PDF reaches the Classifier with non-empty Markdown. No assertion about headings.
- An image-only PDF ends at `EXTRACTION_EMPTY` with the original present in the raw vault, and is not
  routed to the Classifier.
- A file whose conversion times out ends at `EXTRACTION_FAILED` with a non-blank reason detail, and
  the Extractor thread processes the next document in the same test.
- The original is in the raw vault with a `document_copy` row before conversion is attempted, proven
  by a test in which conversion throws.
- Front matter on the written Markdown names the converter and its version, and `probe()` is called
  once rather than per document.

## Contingent on P2.8's measurements

Unchanged from ADR28: the format census and the scanned-PDF share have not been run. If either
trigger fires, P2.9's implementation class changes and this story stands as written.
