# Story P2.5 — Indexer Real Logic

## Overview

Indexer writes classified documents to the vault's target subfolder and triggers Smart Connections MCP indexing. Marks documents as indexed in the database.

## Implementation Requirements

- Resolve source document copy from appropriate vault area
- Move document to indexing vault area with proper naming
- Call SmartConnectionsMonitor to trigger MCP indexing
- Update Document status to indexed stage
- Retire source copy via DocumentCopy.retire()
- Handle file I/O errors and MCP communication failures
- Update document metadata (indexing timestamp, location)

## Smart Connections Integration

- SmartConnectionsMonitor is an empty class that needs implementation
- Call Obsidian Smart Connections MCP server to index the document
- MCP client setup is a prerequisite (P2.5 has unanswered "how does Java talk to MCP" question)

## Acceptance Criteria

- Classified documents written to vault indexing area
- Smart Connections indexing triggered via MCP
- Document status updated to indexed
- Source copy retired with end_date timestamp
- File move operations atomic (no partial writes)
- Failures logged with appropriate error detail
