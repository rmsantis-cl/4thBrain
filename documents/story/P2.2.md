# Story P2.2 — Ingestor Real Logic

## Status

**COMPLETED 2026-09-08.** Implemented from `documents/plan-P2.2.md` by an agent in its own worktree,
merged into `v04` after P2.1. `Ingestor.doTheThing` is now materialise → validate → archive → route.
New `com.fourthbrain.persistence.VaultNaming`, a new `ingestor:` config block, and
`IngestorRoutingTest` grown from 4 tests to 20. `gradle build` green.

**The design gate produced ADR29**, currently at `documents/design/ADR29-ingestor-boundary.md` — a
standalone file, because three agents writing ADRs concurrently could not all append to `ADRS.md`
without conflicting. **It still has to be folded into `documents/design/ADRS.md`.**

### Two acceptance criteria are re-mapped by ADR29, not met as written

- **"Files in RAW_DIR are processed"** — struck. The Ingestor is a queue consumer; `Actuator.run()`
  blocks on `take()` and there is no timer or idle hook. ADR26 decision 1 makes `startChain` the only
  entry point, and Story P2.7 already owns watching the directory. `$RAW_DIR` becomes the archive
  *destination* instead: the original is copied there with a `raw` copy row, which is what ADR28's
  failure semantics assume and what nothing was doing — `VaultArea.RAW` and `vault.raw` had both been
  defined and referenced by nothing.
- **"Messages route to TextExtractor"** — text now routes to **`Classifier`**. No string
  `"Classifier"` was returned anywhere in `src/main` before this: the stage was registered, threaded,
  and unreachable. This is the single most consequential line in the story.

### Other behaviour changes worth knowing

- **A captured note now reaches the vault.** Text arriving through `/api/ingest/capture` had no file
  and no `document_copy` row, so the Indexer found nothing to move and the document stopped. The
  Ingestor writes it to `${vault.tmp}` as explicit UTF-8 and records the copy.
- **PDF, DOCX, PPTX, XLSX, EPub, RTF and ODT stop with a warning naming the format** rather than
  parking at an Extractor that only unzips. PDF was previously classed as *text* and indexed as
  unparsed bytes, which was worse than stopping. P2.3 flips that row when the converter exists.
- **`VaultNaming` is deliberately not a copy of `IngestionController.newName`.** That loop tests
  `dir/prefix` and lets the caller append the extension afterwards, so two notes with the same first
  line both resolve to `hello-world` and the second overwrites `hello-world.md`. The extension is
  carried through the loop instead.

### Departure from the plan

The plan said persist metadata with `documentService.updateDocument(id, doc)`. That merges every
non-null field including `status`, and the in-memory status is stale mid-chain — `updateDocumentStatus`
writes the row without touching the object — so passing the live document would have undone the run
loop's write. A fresh `Document` carrying only `name`, `extension` and `mimeType` is passed instead,
with a test asserting no status rides along.

**Outstanding:** no live run. The agent was instructed not to start the application, so plan
verification step 3 (bootRun plus real POSTs) is unrun and every check is a unit test.

## Overview

Ingestor reads files from `$RAW_DIR`, validates them, and creates Document records for downstream processing. Enqueues TextExtractor messages to begin the extraction pipeline.

## Implementation Requirements

- Read files from configured RAW_DIR directory
- Create Document records with initial metadata
- Copy structured files to incoming vault area if appropriate
- Route to TextExtractor via Coordinator
- Handle file not found and read errors
- Log file ingestion with size and type information

## Acceptance Criteria

- Files in RAW_DIR are processed and Document records created
- Document status transitions correctly through the ingestion stage
- File validation catches missing or corrupt inputs
- Messages properly route to TextExtractor for processing
