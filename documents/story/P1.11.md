# Story P1.11 — Coordinator Entry Point & Message Addressing

## Problem

There are two ways to start a pipeline. One throws, and the tests use it.

`Coordinator.startChain(long)` is an unimplemented stub that throws `UnsupportedOperationException`. Nothing in `src/main` calls it — `IngestionController.java:134` uses `sendMessage("Ingestor", doc)` instead — but eleven assertions across `IngestionControllerTest` verify `startChain` was called. Production and tests disagree about the entry point.

`sendMessage` has its own defect. It builds `new Message(null, get(actuator), doc)`, leaving `from` null. `Message.id()` calls `from.getName()` unguarded, and `Message.toString()` calls `id()`, so logging any message created this way throws an NPE.

The class is also incoherent: `registry` and `actuator` are static while `sendMessage`, `getStatusCounts` and `startChain` are instance methods on a `@Component`. State is shared process-wide but reached through an injected bean, so tests cannot isolate it.

## Change

Design settled in `documents/design/ADRS.md` (ADR26).

1. `startChain(long documentId)` is the only entry point. `sendMessage` is deleted; the controller calls `startChain` directly.
2. `startChain` loads the document **once**, sets its status to the first stage, and enqueues it to `Ingestor` inside a `Message` carrying that same `Document` instance. Every actuator downstream reads and mutates the object it was handed rather than re-fetching by id — `Actuator.run()` already passes the same `Document` from hop to hop this way, and `startChain` must join that pattern rather than inventing a per-hop reload. `DatabaseService` is touched only to load the document at chain start and to persist each status transition. Fail loudly on an unknown id.
3. Give `Message` a real sender, or make `from` legitimately optional and null-safe. If a message can originate outside an actuator, `id()` and `toString()` must handle it.
4. Make the state non-static, or make the whole class static and stop injecting it. Mixing them breaks test isolation.

## Acceptance Criteria

- `Coordinator.startChain(long)` loads a document by id exactly once, sets status to the first stage, enqueues it to Ingestor inside a `Message` carrying the loaded `Document`
- No actuator re-fetches a document from the database while it already holds that document via `Message`
- `startChain` fails with a clear error on an unknown document id
- `Message` objects created via any entry point can be logged without NPE
- Test isolation works: a second `@SpringBootTest` does not inherit actuators from the first
