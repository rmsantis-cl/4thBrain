# Story P3.5 — Upgrade to JUnit 5

## Overview

This story was written as a migration. It was not one. By the time it was written the test code was
already Jupiter throughout, and what remained was a dangling JUnit 4 API on the test classpath.

`build.gradle` declared `junit:junit:4.13.2` with **no `junit-vintage-engine` behind it**, alongside
`useJUnitPlatform()`. JUnit 4 was therefore present as an API with no engine to run it: a test
written with `org.junit.Test` compiled cleanly, produced no warning, and was then silently not
executed — Gradle reports the class with zero tests rather than failing. That is worse than a broken
build, because it looks like a pass. Removing the dependency turns that silent skip into a compile
error.

The rest of this file is kept as reference material for the migration that had already happened. See
`documents/P3.5-UPGRADE-PLAN.md` for the plan this was executed from.

## Implementation Requirements

- Update `build.gradle`: remove `junit:junit:4.13.2`. Jupiter is already on the test classpath,
  supplied transitively by `spring-boot-starter-test`, so nothing replaces it.
- Replace `@RunWith` and `@Rule` with JUnit 5 equivalents — nothing to do, none exist
- Update test class annotations: `@Test`, `@DisplayName`, lifecycle annotations — already Jupiter
- Migrate Spring Boot test annotations to work with Jupiter — already so
- Update Mockito integration for JUnit 5 — already so
- Remove JUnit 4 specific imports — none exist

## Key Changes (reference)

| JUnit 4 | JUnit 5 |
|---------|----------|
| `@RunWith(SpringRunner.class)` | `@SpringBootTest` (works with Jupiter) |
| `@Rule` | `@ExtendWith` (extension model) |
| `@Before` / `@After` | `@BeforeEach` / `@AfterEach` |
| `@BeforeClass` / `@AfterClass` | `@BeforeAll` / `@AfterAll` |
| `@ParameterizedTest` (add-on) | `@ParameterizedTest` (built-in) |

## Compatibility

- Spring Boot 3.2.0 includes Jupiter in `spring-boot-starter-test`
- MockitoExtension for better Mockito integration

## Acceptance Criteria

- All tests migrated to JUnit 5 annotations
- `gradle test` passes with Jupiter engine
- No JUnit 4 imports in test classes
- All existing test functionality preserved
- IDE recognizes tests as JUnit 5

## Status

Implemented and verified 2026-09-07.

`junit:junit:4.13.2` removed from `build.gradle`. `@MockBean` replaced with `@MockitoBean`
(`org.springframework.test.context.bean.override.mockito.MockitoBean`) in `IngestionControllerTest`,
two occurrences plus the import — deprecated since Spring Boot 3.4 and removed in Boot 4, so it
would have broken on the next Boot bump. That is not JUnit 4 and so is strictly outside the story as
written; it was folded in because it is the same file and the same concern, and is recorded here
rather than left to be discovered.

Verification:

- Baseline before the change: 28 tests executed, 23 failures, 0 skipped.
- After: 28 executed, 23 failures, 0 skipped — identical, with `compileTestJava` and `test` both
  re-running rather than reporting UP-TO-DATE. All 23 failures are `IngestionControllerTest`
  asserting P1.13's endpoint contract (`jobId`, implemented `/text` and `/url`); none is a P3.5
  failure and none changed. `ActuatorManagerTest` is 5 for 5 before and after.
- `gradlew dependencies --configuration testRuntimeClasspath` shows no `junit:junit`. Jupiter 5.12.2
  and `junit-platform-launcher` 1.12.2 are there, via `spring-boot-starter-test`.
- The trap itself was checked rather than assumed: a temporary test class importing `org.junit.Test`
  now fails compilation with `package org.junit does not exist`, where before it would have compiled
  and reported zero tests. The probe was deleted and `compileTestJava` is clean.

`gradlew test` still exits non-zero, and that is expected — it does so for P1.13's reasons, which
P1.11's plan addresses by disabling those methods until P1.13 rewrites them.
