# Story P1.14 — View Layer & Template Engine

Closes BUG-001. Design is ADR25 in `documents/design/ADRS.md`.

## Problem

`UIController` and `AdminController` are `@Controller` classes returning view names, and no view
technology is on the classpath. All five endpoints 404. See `documents/bug/BUG-001.md` for the full
diagnosis.

## Scope

Add Thymeleaf and put every served page where the resolver looks for it.

1. **`build.gradle`** — add `implementation 'org.springframework.boot:spring-boot-starter-thymeleaf'`.
2. **Move** `src/main/resources/static/index.html` → `src/main/resources/templates/index.html`.
   No edits to the file's content.
3. **`UIController`** — keep `@GetMapping("/chat")` returning `"index"`. Change `@GetMapping("/")`
   to return `"index"` directly rather than `redirect:/chat`, so the root serves the page in one
   request instead of a round trip.
4. **`AdminController`** — no change needed. Its three view names already match files in
   `templates/`.
5. **Replace the `System.out.println("STUB: ...")` calls** in both controllers with `@Slf4j`
   logging, per the project's logging principle. These are the same lines being edited, and
   `System.out` is not how anything else in the codebase logs.

Out of scope: the content of any page, the admin pages' behaviour, and anything the pages fetch.

## Verification

The application does not start until P1.9 lands, so the acceptance criteria below cannot be
exercised before then. The code change does not depend on P1.9 and can be written and reviewed
first.

## Acceptance criteria

- [ ] `GET /` returns 200 and the seven-panel page body
- [ ] `GET /chat` returns 200 and the same body
- [ ] `GET /admin`, `GET /admin/db`, `GET /admin/api/docs` each return 200 and render their page
- [ ] The nav bar and panel switching work — these are built by the inline script's `${...}`
      template literals, so a blank or malformed nav is the signal that Thymeleaf processed the
      script when it should not have
- [ ] Browser console shows no 404s and no JavaScript errors
- [ ] `src/main/resources/static/` no longer contains `index.html`
- [ ] Neither controller calls `System.out.println`

## Notes

The `${...}` collision between JS template literals and Thymeleaf expressions is the one thing
likely to go wrong here. It is safe by default and the reasoning is written up in ADR25's
consequences. If a script block ever does need protecting, `th:inline="none"` is the escape hatch.
