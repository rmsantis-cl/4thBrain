# Story P2.1 — OllamaClient & ConcurrencyGate

## Overview

RestTemplate wrapper that calls the Ollama API at `http://localhost:11434/v1`. A Semaphore enforces concurrency=1 so only one LLM call is in flight at a time. Classifier and Briefing use OllamaClient to reach the local model.

## Implementation Requirements

- `OllamaClient.java` — wraps RestTemplate for `/v1/chat/completions` endpoint
- `ConcurrencyGate.java` — Semaphore(1) wrapper that blocks until prior call finishes
- Inject into `Classifier` and `Briefing` actuators
- Configuration: Ollama URL from `application.yaml` (`ollama.url: http://localhost:11434`)

## Acceptance Criteria

- OllamaClient successfully calls Ollama and parses responses
- ConcurrencyGate enforces concurrency=1
- Classifier and Briefing wait for prior LLM call to finish
- Error responses are logged and propagated appropriately

# Story P2.1 — OllamaClient & ConcurrencyGate

## Status

**COMPLETED 2026-09-08.** Implemented from `documents/plan-P2.1.md` by an agent in its own worktree,
then merged into `v04` first of three. New package `com.fourthbrain.llm`: `OllamaClient` (interface),
`OllamaHttpClient`, `ConcurrencyGate`, `OllamaException`. The `ollama:` block gained
`connect-timeout-ms`, `read-timeout-ms` and `acquire-timeout-ms`, each with a `@Value` default so an
older config still starts.

Verified: `gradle build` green, 11 new tests (5 `ConcurrencyGateTest`, 6 `OllamaHttpClientTest`), 91
tests total across the suite with nothing skipped.

**One acceptance criterion is re-mapped, not met as written.** "Classifier and Briefing wait for the
prior LLM call to finish" — the gate is what enforces waiting, and it is built and tested. The
injection is not this story's: `Classifier.java` belonged to a sibling agent and is done under P2.4,
and **no `Briefing` class exists in `src/main`** — `application.yaml` has reserved a thread count for
one since the skeleton, and P2.6 is the story that writes it.

Two design points settled during implementation and worth keeping:

- **`tryAcquire` with a timeout, not a bare `acquire()`.** A hung model behind an unbounded gate
  parks an actuator thread forever, and a status-driven pipeline shows nothing — the same
  invisibility ADR28 argues against for stalled conversions.
- **The gate is fair.** One permit shared between the Classifier and a future Briefing can starve one
  of them under unfair mode.

**Outstanding: the client has never called a real Ollama.** All verification is against
`MockRestServiceServer`. The agent was instructed not to start the application (four agents and a
running instance would have contended for port 8080), so plan verification steps 3 to 5 — a live round
trip, the error path with the service stopped, and the elapsed-time measurement ADR28's trigger 3
wants — are all unrun. **P2.10's status is still contradictory** (the tracker says COMPLETED, its own
story header says READY), so whether anything answers on `localhost:11434` is itself unconfirmed.

Merge note: `OllamaException` was specified in prose rather than source, so the P2.4 agent's
independent copy differed and produced an add/add conflict. This story's version won, as both plans
said it should, and `ClassifierTest` was adapted to its constructor.
