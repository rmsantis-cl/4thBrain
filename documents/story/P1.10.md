# Story P1.10 — Actuator Run Loop

## Problem

`Actuator.run()` burns a core per actuator and cannot stop.

`Actuator.java:68` polls with `getQueue().poll()`, which returns null on an empty queue, and `:69` dereferences it immediately. The NPE is swallowed by the loop's own `catch (Throwable)` at `:95`, and the loop restarts with no sleep or back-off. With five idle actuators that is five cores spinning — visible in the boot log as an unbroken stream of `Main loop error`.

### Subsidiary Faults

- `Thread exiting.` is logged at `:99`, inside the `while` body rather than after it, so it prints every iteration
- `running` is private with no way to clear it, so `while (running)` never ends. Threads are daemons, so the JVM exits, but nothing can stop an actuator deliberately

## Change

1. Replace the queue with a `BlockingQueue` and poll with `take()`, or `poll(timeout)` if the loop needs to observe a stop flag. This is what P1.3 specified — "a dedicated thread running a BlockingQueue.take() loop" — so this restores the intended design. An idle actuator then costs nothing.
2. Guard the message anyway: a null or document-less message is logged and skipped, never dereferenced.
3. Move `Thread exiting.` after the loop.
4. Add a `shutdown()` that clears `running` and interrupts the thread, and have the loop treat `InterruptedException` as a stop signal rather than an error. Call it from a Spring lifecycle hook.
5. Narrow `catch (Throwable)` to `catch (Exception)`, and let the loop continue only for a failure processing one message.

Note that `Actuator.map` and `Actuator.registry` (`:27-28`) are dead: every subclass overrides `getQueue()` with its own static queue. Remove them.

## Acceptance Criteria

- An idle application shows no `Main loop error` entries and no measurable CPU use from actuator threads
- A message with a null document is logged once and skipped; the loop continues
- `shutdown()` stops an actuator's thread within a bounded time
- `Thread exiting.` appears exactly once per actuator, at shutdown

## Status

Implemented 2026-09-06, in the same pass as P1.9 and verified with it. The queue is a `BlockingQueue` polled with `take()`, a message with no document is logged and skipped, `Thread exiting.` sits after the loop, `shutdown()` clears `running` and interrupts with a bounded `join`, the catch is narrowed to `Exception`, and the dead `map`/`registry` instance fields are gone. The `InterruptedException` handler now also breaks out of the loop — without that, a spurious interrupt left `running` true and `take()` threw immediately on the flag, reaching the same busy-spin by another route. An idle application logs no `Main loop error` and its actuator threads use no measurable CPU.
