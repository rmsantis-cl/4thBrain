# Story P1.16 — Crash Recovery

Drafted as P1.15 on the branch that carried the P1.9/P1.10 verification work. Renumbered to
P1.16 when that branch was rebased, because P1.14 was already taken by View Layer & Template
Engine and the renumber cascaded.

## Problem

Documents can be left in a transient status if an actuator or the application crashes
mid-processing.

A document with status `ingesting` when the application exits has no actuator-owned queue entry
— it was already polled. On restart that document sits in `ingesting` forever: no actuator picks
it up, and no endpoint can tell what went wrong.

## Change

1. On startup, query for documents in any transient status — the gerund forms `ingesting`,
   `extracting`, `classifying`, `indexing`.
2. For each, look at the last update's timestamp. If it is older than a configured threshold
   (1 hour since the last status change), assume the previous actuator crashed and requeue the
   document to that stage.
3. Handle documents with no status history — newly created but never started. Requeue them to
   `Ingestor`.
4. Log a recovery report: how many documents were requeued, from which stages. This shows up in
   the startup log and flags a crashed run.
5. Reconcile with the vault: a document marked `indexing` but already present in the vault is
   marked indexed rather than requeued, so an indexer crash that persisted its work is not
   re-run.

## Acceptance Criteria

- A document left in `ingesting` with a timestamp more than 1 hour old is requeued to the first
  actuator on startup
- A document in `indexing` that is present in the vault is marked `indexed` instead of requeued
- The startup log contains a recovery report — "Recovered 3 documents from ingesting, 1 from
  classifying"
- Requeue does not duplicate work: one document's ID is not enqueued twice in a single startup
- A document in a transient status for less than 1 hour is left alone; it may still be in
  progress

## Phase Placement

Placed in Phase 1, but it is operational rather than structural work and may be better deferred
until the core pipeline is proven — Phase 2 or Phase 3.
