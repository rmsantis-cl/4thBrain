# P1.11 Fix Plan

Execution plan for Story P1.11 (Coordinator Entry Point & Message Addressing). Unlike P1.9, this is
a build-it plan: none of the code exists yet.

## Verified state of the working tree

Read on 2026-09-07, against `v04-1`:

| Claim in the story | Verified |
|---|---|
| `startChain(long)` throws `UnsupportedOperationException` | Yes — `Coordinator.java:53-56`, parameter is literally named `anyLong` |
| Nothing in `src/main` calls `startChain` | Yes — the only 11 references are `IngestionControllerTest` |
| `IngestionController` uses `sendMessage` instead | Yes — `IngestionController.java:134` |
| `sendMessage` leaves `from` null | Yes — `Coordinator.java:45`, `new Message(null, get(actuator), doc)` |
| `Message.id()` dereferences `from` unguarded | Yes — `Message.java:45` |
| `registry` static, `sendMessage`/`getStatusCounts`/`startChain` instance | Yes — `Coordinator.java:27` vs `:44,48,53` |

Two corrections to the story's wording, neither of which changes the work:

- The NPE is **latent, not certain**. Nothing on the live path logs a `Message` object today, so
  `Message.toString()` is never reached. It fires the first time anyone writes
  `log.debug("... {}", message)` — which is exactly the kind of line added while debugging the
  thing that is already broken. Treat it as a trap, not a current crash.
- `sendMessage` has a second unguarded dereference the story does not mention:
  `get(actuator).getQueue()` NPEs when the name is unregistered. `Actuator.run()` already got a
  null check for this in P1.9; `sendMessage` never did.

Two further defects found while reading, both in scope because the fix touches the same lines:

- **`Message.builder()` never stamps `createdAt`.** Lombok's `@Builder` leaves it null, so every
  message built at `Actuator.java:97`, `Extractor.java:206` and `Clipper.java:144` carries
  `createdAt=null`, which `toString()` then prints. Only the explicit 3-arg constructor sets it, and
  that is the constructor being deleted.
- **`Message.id()` misspells its own output** — `"Mesasge[...]"`, `Message.java:45`.

Out of scope but worth recording, because it will look like a P1.11 regression otherwise:
`getStatusCounts()` returns **queue depths keyed by actuator class name** (`Ingestor`, `Extractor`),
while `StatusController.java:22-26` looks up `ingesting`, `extracting`, `indexed`. Every key misses,
so `/api/status` returns five zeros regardless of pipeline state. That is Story P1.12's whole
subject. P1.11 must not fix it, and must not make it worse.

## Design gap — resolve before implementing

Per `.claude/rules/design-before-implementation.md`, P1.11 has a Story but no design artifact. The
story's "Change" section leaves two decisions genuinely open ("express `sendMessage` in terms of it,
**or** delete it"; "make the state non-static, **or** make the whole class static"). Those are
architecture decisions, not implementation details.

**Step 0 of this plan is to write ADR26** in `documents/design/ADRS.md`, recording:

1. `startChain(long documentId)` is the pipeline's only entry point. `sendMessage` is deleted.
2. `Message.from` is legitimately optional — a message can originate at the REST boundary, outside
   any actuator — so `id()` and `toString()` must render a null sender rather than reject it.
3. The Coordinator registry becomes **instance state on the `@Component`**, not static.

The reasoning for (3) is the part worth writing down, because the cheap fix does not work. Clearing
a static registry on context close does **not** give test isolation: Spring caches test contexts, so
when a second `@SpringBootTest` class with different properties builds a second context, the first
context is still open and its actuators are still registered. Both sets then live in one static map
and `get("Ingestor")` returns whichever registered first. Only per-context state fixes this, which
is why the AC "a second `@SpringBootTest` does not inherit actuators from the first" forces the
larger change.

Record the debt in `documents/DESIGN-DEBT.md` (the file the rule names does not yet exist — create
it) and mark it Cleared with a pointer to ADR26 in the same pass.

## The change

### 1. `Coordinator` — instance state, one entry point

```java
@Component
public class Coordinator {

    @Autowired
    private DocumentService service;

    /** First stage of the pipeline. */
    private static final String FIRST_STAGE = "Ingestor";

    // Per-context, not per-JVM: two Spring contexts in one JVM (which is what the
    // test cache produces) must not see each other's actuators (ADR26).
    // Still concurrent: ActuatorManager registers on the main thread at startup,
    // every actuator thread reads on each routing hop.
    private final Map<String, List<Actuator>> registry = new ConcurrentHashMap<>();

    public void register(Actuator a) { ... }          // was static
    public List<Actuator> instancesOf(String name) { ... }   // was static
    public Actuator get(String name) { ... }          // was static

    public void startChain(long documentId) {
        Document doc = service.getDocumentById(documentId)
                .orElseThrow(() -> new IllegalArgumentException(
                        "startChain: no document with id " + documentId));
        Actuator first = get(FIRST_STAGE);
        if (first == null) {
            throw new IllegalStateException("startChain: no '" + FIRST_STAGE + "' registered");
        }
        service.setStatus(doc, first.getGerund());
        first.enqueueMessage(Message.to(first, doc));
        log.info("chain started doc={} -> {}", documentId, first.getName());
    }
}
```

`startChain` sets the first stage's gerund before enqueueing, per the acceptance criteria. The run
loop sets it again on pickup; that is idempotent, and the point of setting it here is that a
document is visibly `ingesting` between the HTTP response and a thread getting to it, rather than
sitting at `New` with nothing to say it is queued.

`sendMessage` is deleted.

### 2. Callers of the (previously static) registry

Making the registry an instance field means four call sites need a `Coordinator` reference. All four
are Spring-managed, so this is injection, not plumbing:

| File | Now | After |
|---|---|---|
| `ActuatorManager.java:81` | `Coordinator.register(a)` | `@Autowired Coordinator coordinator;` → `coordinator.register(a)` |
| `Actuator.java:90` | `Coordinator.get(n)` | `@Autowired` field on `Actuator` (inherited by all five subclasses) |
| `Extractor.java:198` | `Coordinator.get("Ingestor")` | inherited field |
| `Clipper.java:136` | `Coordinator.get("Ingestor")` | inherited field |

Actuators are created through `ObjectFactory` (P1.9), so `@Autowired` on the abstract base is
populated exactly the way `service` already is. Injection completes in `ActuatorManager`'s
`@PostConstruct` phase A, before registration in phase B and long before threads start in phase C —
the ordering P1.9 established already covers this.

### 3. `IngestionController`

```java
- coordinator.sendMessage("Ingestor",savedDoc);
+ coordinator.startChain(savedDoc.getId());
```

One line, `IngestionController.java:134`. The `/text` and `/url` endpoints stay stubbed — they are
Story P1.13.

### 4. `Message` — null-safe sender, stamped clock, no `@Data`

Replace `@Data`/`@Builder`/`@AllArgsConstructor` and the public constructor with `@Getter` and two
static factories, so `createdAt` cannot be forgotten and `from` cannot NPE:

```java
public static Message to(Actuator target, Document doc)              // external origin, from == null
public static Message between(Actuator from, Actuator to, Document doc)
```

- `id()` renders a null sender as `external` instead of dereferencing it, and the `Mesasge` typo goes.
- `@Data` goes because it generates `equals`/`hashCode` across an `Actuator` (a `Thread`) and a JPA
  entity, for a value that is never compared or keyed. `@Getter` is what the class actually uses.
- Three call sites move to `Message.between(...)`: `Actuator.java:97`, `Extractor.java:206`,
  `Clipper.java:144`. `Coordinator.startChain` is the only user of `Message.to(...)`.

## Tests

**New — `CoordinatorTest`** (`@SpringBootTest`, same property block as `ActuatorManagerTest`):

- `startChain` on a saved document sets its status to `ingesting` and puts one message on the
  Ingestor queue.
- `startChain(999999)` throws `IllegalArgumentException` naming the id.
- `Message.to(ingestor, doc).toString()` returns a string containing `external` and does not throw —
  the regression test for the latent NPE.
- `Message.between(...)` stamps a non-null `createdAt`.

**Changed — `ActuatorManagerTest`.** Its five tests assert against `Coordinator.instancesOf(...)`
statically; they become `@Autowired Coordinator` calls. The class comment at
`ActuatorManagerTest.java:16-19` explicitly says "Making that state non-static is P1.11" — delete it
when the state moves.

**Deliberately left failing — `IngestionControllerTest`.** Eleven of its assertions become correct
under this change, but the class as a whole still fails, and not for P1.11 reasons: `/text` and
`/url` return `{"not":"implemented"}`, and `/file` returns `"id"` where the test reads `"jobId"`.
That is Story P1.13's contract. Rather than leave `gradlew test` red with no signal about why, mark
the affected methods `@Disabled("Story P1.13 — endpoint contract")` in this pass and delete the
annotations in P1.13. The suite stays green and the gap stays visible.
