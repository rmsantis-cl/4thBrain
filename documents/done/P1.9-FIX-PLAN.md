# P1.9 Fix Plan

`documents/design/STARTUP-SEQUENCE.md`.

## Part 1 â€” Three defects in the new code

### 1.1 The Coordinator registry is not safely published

`Coordinator.java:26` writes under `synchronized (registry)`; `:32` reads with no
synchronization, from a plain `HashMap`, on a different thread than the one that registered.

Replace the map and drop the manual lock:

```java
private static final Map<String, List<Actuator>> registry = new ConcurrentHashMap<>();

public static void register(Actuator a) {
    registry.computeIfAbsent(a.getClass().getSimpleName(), k -> new CopyOnWriteArrayList<>()).add(a);
}
```

Registration happens once at startup and reads happen on every routing hop, so
`CopyOnWriteArrayList` is the right trade.

### 1.2 `Actuator.run()` dereferences a null next-actuator

`Actuator.java:90` takes `Coordinator.get(n)` and `:96` calls `follow.getName()` with no null
check. A subclass returning an unregistered name NPEs inside the loop. `Extractor.java:199` and
`Clipper.java:137` already guard this; the base loop should match them.

Guard before use, log the unknown name, and let the document stop rather than throwing.

### 1.3 A spurious interrupt hot-spins the loop

`Actuator.java:102-104` catches `InterruptedException`, re-sets the interrupt flag, and falls
through to `while (running)`. On the shutdown path this is fine, because `shutdown()` clears
`running` before interrupting. On any other interrupt `running` is still true, so `take()` sees
the flag, throws immediately, and the handler re-sets it â€” a tight loop burning a core. This is
the same busy-spin P1.10 removed, reached by a different route.

Add `break` to the `InterruptedException` handler. `Thread exiting.` after the loop still runs.

## Part 2 â€” Configuration

In `src/main/resources/application.yaml` under `actuators.threads`:

- Add `clipper: 1`. `ActuatorManager` already defaults to 1 via `${actuators.threads.clipper:1}`,
  so behaviour does not change â€” this makes the one actuator without an entry explicit, as the
  story asks.
- `briefing: 1` names a class that does not exist in `src/main/java`. Remove it, or keep it with a
  comment marking it reserved for Phase 2. Nothing reads it either way.

## Part 3 â€” Source level

`build.gradle:11` declares `sourceCompatibility = '17'`, but `Coordinator.java:33` and `:42` call
`List.getFirst()`, a Java 21 API. Gradle sets `-source`/`-target` without `--release`, so this
compiles against the installed JDK 25 and works â€” the declared level is simply not true.

Set `sourceCompatibility = '21'`. Spring Boot 3.5 requires 17 or higher, Temurin 25 is installed,
and the code already uses Java 21 idioms.

## Part 4 â€” Test

New: `src/test/java/com/fourthbrain/actuators/ActuatorManagerTest.java`

Covers the criteria that are assertable without a running server:

- `actuators.threads.<name>: N` produces exactly N registered instances â€” set `ingestor: 2` via
  `@TestPropertySource` and assert the registry, not log lines.
- `Coordinator.get(...)` returns a registered instance for all five actuator names.
- Every actuator holds a non-null `DocumentService` before processing.

Two things this needs:

**A registry accessor.** `Coordinator.registry` is private with no size query, so the first
criterion cannot be asserted today. Add `public static List<Actuator> instancesOf(String name)`
returning an unmodifiable view, empty when absent. `get()` can then be expressed in terms of it.

**An isolated database.** `@SpringBootTest` builds the full context, including the DataSource.
Point it at a scratch file so the test never touches `data/fourthbrain.db`:

```java
@TestPropertySource(properties = {
    "spring.datasource.url=jdbc:sqlite:build/test-fourthbrain.db",
    "spring.jpa.hibernate.ddl-auto=none",
    "spring.sql.init.mode=always",
    "actuators.threads.ingestor=2"
})
```

Note that `Coordinator`'s registry is `static`, so it survives across contexts and a second test
class would inherit this one's actuators. Keep to a single context for now; making that state
non-static is P1.11 item 4, not this story.

Run it scoped â€” `gradlew test --tests '*ActuatorManagerTest'`. A bare `gradlew test` also runs
`IngestionControllerTest`, whose 24 tests all fail against the current controller. Those belong to
P1.13 and must not be read as a regression here.

## Part 5 â€” Boot verification

The environment needs preparing first; two of these will otherwise stop the boot.

1. **Release the database file.** `data/fourthbrain.db` was found locked by another process â€” two
   `java` processes were running with nothing listening on 8080, so Gradle daemons or the IDE
   language server rather than the app. Run `gradlew --stop`, and confirm the handle is gone
   before continuing.
2. **Replace the stale database.** A 48 KB `data/fourthbrain.db` predates P1.8. `schema.sql` is
   all `CREATE TABLE IF NOT EXISTS`, so it will not upgrade an existing file, and
   `ddl-auto: validate` will fail when it finds `document.path` present and `document_copy`
   missing. P1.8 records the remedy: delete it and let the schema be created fresh. Move it aside
   rather than deleting outright.
3. **Create the vault directories.** `vault/`, `vault/incoming`, `vault/indexing` and `vault/raw`
   are all missing; only `tmp/` exists. Not required for the context to start, but required before
   anything is processed.

Then `gradlew bootRun`, and check the log against P1.9's criteria:

| Expected | Criterion |
|---|---|
| `Created 1 <Type> instance(s)` for each of the five types | exactly N instances |
| `Registered 5 actuator instance(s)` | registration completes |
| `Started 5 actuator thread(s)` | Phase C runs |
| `Started FourthBrainApplication` | context does not abort |
| No `IllegalThreadStateException` | thread started once |
| No `Main loop error` flood, actuator threads at idle CPU | P1.10's spin is gone |

Then stop it and confirm shutdown: `Thread exiting.` exactly once per actuator, followed by
`Shut down 5 actuator thread(s)`.
