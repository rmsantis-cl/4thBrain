# Plan — P1.11, P1.13 and P1.17 in one change

`documents/P1.11-FIX-PLAN.md` (v2.0) stages the same three stories sequentially, plus a fourth
(P1.18, the composer itself). This plan collapses stages 1 to 3 into a single change and states what
that buys, what it costs, and where the boundary sits. P1.18 stays out; see *Scope boundary*.

Nothing here contradicts the staged plan's findings. They were re-verified against the tree on
2026-09-07 and are carried forward.

## Why these three can be one change

The staged plan sequences on two constraints, and only one of them is about code.

**P1.13 needs a working `startChain`.** Real, and it stays real: the controller cannot start a
pipeline the Coordinator cannot start. Inside one change this is a compile-order constraint, not a
delivery-order one — step 2 comes before step 5 in the same pass.

**P1.17 must land before P1.13, because what the endpoints accept depends on what the composer
sends.** Also real, but it is a *design* ordering. `.claude/rules/design-before-implementation.md`
already requires the design to exist before the code does. Doing the spike's design work at the front
of the change satisfies both the rule and the ordering, without a separate delivery.

What makes the merge safe is an asymmetry inside the spike's output. The spike answers two different
kinds of question:

| Spike output | Touches the endpoint contract? |
|---|---|
| Capture-versus-converse routing (A, B or E) | No. All three post the same body to `/api/ingest/text` |
| URL detection rule | No. It decides which endpoint the browser calls, not what the endpoint accepts |
| Text plus a file in one send | **Yes** — one document or two |
| Several files at once | **Yes** — one request or several |
| Where tags live | **Yes** — the field the request carries |
| Response shape the composer reads | **Yes** |

The four that matter are settled by writing them down, not by clicking a prototype. The routing
decision is the one the prototype exists to test, and it is the one the Java does not depend on. So
the prototype can run late in the change, or even after it, without putting any Java at risk.

### What one change buys

- **The `@Disabled` dance disappears.** Staged, stage 1 has to mark eleven `IngestionControllerTest`
  assertions `@Disabled("Story P1.13")` to get a green suite, and stage 3 deletes the annotations.
  Here the class is rewritten once against the final contract. There is never a commit whose suite is
  green because tests are switched off.
- **`index.html` is edited once.** The three panels read `data.jobId` at lines 462, 484 and 507. The
  controller returns `id`. Staged, that inconsistency is half-fixed for the length of stage 1.
- **The `Ingestor`/`Clipper` URL-field change lands beside the endpoint that needs it.** On its own it
  is a change with no caller.
- **One ADR pass.** ADR26 and ADR27 are written together, which is where the two open cross-cutting
  questions actually live: status-write ownership, and the response shape.

### What one change costs

- **A larger blast radius per merge.** Mitigated by keeping commits granular inside one branch — see
  *Commit shape*.
- **The spike stops being throwaway in the usual sense.** It now prototypes against endpoints that
  work in the same tree. That is a better prototype, but the "prototype against stubbed responses"
  instruction in `SPIKE-UNIFIED-COMPOSER.md:158` and the dependency paragraph at `P1.17.md:66-69`
  both assume P1.13 comes later, and need a one-line amendment when this lands.
- **A half-day timebox inside a multi-day change is easy to overrun.** Hold it: if A and B look equal
  at the halfway mark, take B and record that the choice was close, exactly as the brief says.

P1.17's hard scope line — *"No production code lands under P1.17"* — still holds under this plan. The
composer UI is P1.18. The only `index.html` edit here is `jobId` → `id`, which is P1.13's.

Two findings from the staged plan are worth restating, because they change what gets built.

**The NPE is latent.** Nothing on the current path logs a `Message`, so `toString()` is never reached.
It fires the first time someone adds `log.debug("... {}", message)` while chasing something else.

**A URL document as P1.13 describes it dies at the first hop.** Built with `sourceUrl` set and
`content` empty, it matches neither `isUrl` nor `isTextContent`. `Ingestor` logs "Document type not

Meeting P1.13's own acceptance criteria requires the `Ingestor` and `Clipper` edits in step 4.

## Step 0 — the design gate

No Java until this is done. Both ADRs go in `documents/design/ADRS.md`.

**ADR26, the pipeline's entry contract:**

1. `startChain(long documentId)` is the only entry point. `sendMessage` is deleted.
2. `Message.from` is legitimately optional, because a message can originate at the REST boundary,
   outside any actuator. `id()` and `toString()` render a null sender rather than reject it.
3. The Coordinator registry becomes instance state on the `@Component`, not static. The reasoning has
   to be written down, because the cheap version does not work: clearing a static registry on context
   close gives no isolation, since Spring caches test contexts. A second `@SpringBootTest` with
   different properties builds a second context while the first is still open, both sets of actuators
   live in one static map, and `get("Ingestor")` returns whichever registered first. Only per-context
   state satisfies P1.11's fourth acceptance criterion.
4. A submitted URL is carried on `Document.sourceUrl`. `content` stays empty until something fetches
   the page, so `content` keeps one meaning.
5. One service owns `Document.status` writes, named explicitly. Today both
   `DatabaseService.updateDocumentStatus` (synchronized, ADR17) and
   `DocumentService.updateDocumentStatus` (not synchronized) write it, and the actuator run loop uses
   the unsynchronized one on every stage transition. Decide it here or log it in
   `documents/DESIGN-DEBT.md`; do not pick one per call site.
6. `/text` and `/url` collapse into one endpoint, `POST /api/ingest/capture`, dispatching on whichever
   of a `url` or `text` body key is present. The UI's own URL-detection (already needed for the P1.17
   composer) picks the key; the server does not re-derive the type. `/file` stays separate.
7. One response shape across all three ingest endpoints (step 5).

**ADR26 has since been written** in `documents/design/ADRS.md`, with these seven decisions plus the
explicit statement that a `Message` carries the fully-loaded `Document` rather than an id, so no
actuator re-fetches one it already holds. This plan's step 0 can be treated as satisfied for ADR26;
only ADR27 (the spike's routing decision) remains open.

**ADR27, the composer's routing decision**, from the spike. The four contract-bearing answers in the
table above must be in it before step 5 is written. The routing choice itself — A, B or E — can be
recorded after the prototype runs, since no Java depends on it.

`documents/DESIGN-DEBT.md` does not exist yet. Create it if decision 5 is deferred rather than taken.

## Step 1 — `Message`

Replace `@Data`, `@Builder` and `@AllArgsConstructor` with `@Getter` and two static factories, so
`createdAt` cannot be forgotten and `from` cannot NPE.

```java
public static Message to(Actuator target, Document doc)                  // external origin, from == null
public static Message between(Actuator from, Actuator to, Document doc)
```

- `id()` renders a null sender as `external` instead of dereferencing it, and the `Mesasge` typo goes.
- `@Data` generates `equals`/`hashCode` across an `Actuator` (a `Thread`) and a JPA entity, for a
  value never compared and never used as a key. `@Getter` is what the class actually uses.
- Three call sites move to `Message.between(...)`: `Actuator.java:97`, `Clipper.java:144`,
  `Extractor.java:206`. `startChain` is the only caller of `Message.to(...)`.

## Step 2 — `Coordinator`

```java
@Component
public class Coordinator {

    @Autowired
    private DatabaseService databaseService;

    private static final String FIRST_STAGE = "Ingestor";

    // Per-context, not per-JVM: two Spring contexts in one JVM (which is what
    // the test cache produces) must not see each other's actuators (ADR26).
    // Still concurrent: ActuatorManager registers on the main thread at startup,
    // every actuator thread reads on each routing hop.
    private final Map<String, List<Actuator>> registry = new ConcurrentHashMap<>();

    public void register(Actuator a) { ... }                // was static
    public List<Actuator> instancesOf(String name) { ... }  // was static
    public Actuator get(String name) { ... }                // was static

    public void startChain(long documentId) {
        Document doc = databaseService.getDocument(documentId);
        if (doc == null) {
            throw new IllegalArgumentException("startChain: no document with id " + documentId);
        }
        Actuator first = get(FIRST_STAGE);
        if (first == null) {
            throw new IllegalStateException("startChain: no '" + FIRST_STAGE + "' registered");
        }
        databaseService.updateDocumentStatus(documentId, first.getGerund());
        first.enqueueMessage(Message.to(first, doc));
        log.info("chain started doc={} -> {}", documentId, first.getName());
    }
}
```

`DatabaseService.getDocument` returns a bare null rather than an `Optional`, so the check is explicit.
`startChain` sets the first gerund before enqueueing: the run loop sets it again on pickup, which is
idempotent, and the point is that a document reads as `ingesting` between the HTTP response and a
thread reaching it, rather than sitting at `New` with nothing to say it is queued.

`sendMessage` is deleted, and both of its unguarded dereferences go with it.

## Step 3 — the four static call sites

All Spring-managed, so this is injection rather than plumbing.

| File | Now | After |
|---|---|---|
| `ActuatorManager.java:81` | `Coordinator.register(a)` | `@Autowired Coordinator` field → `coordinator.register(a)` |
| `Actuator.java:90` | `Coordinator.get(n)` | `@Autowired` field on the abstract base, inherited by all five subclasses |
| `Clipper.java:136` | `Coordinator.get("Ingestor")` | inherited field |
| `Extractor.java:198` | `Coordinator.get("Ingestor")` | inherited field |

Actuators are built through `ObjectFactory` (P1.9), so `@Autowired` on the base is populated the same
way `service` already is. Injection completes in `ActuatorManager`'s `@PostConstruct` phase A, before
registration in phase B and well before threads start in phase C.

## Step 5 — `IngestionController`, all three endpoints

`/file`, one line at `:134`:

```java
- coordinator.sendMessage("Ingestor",savedDoc);
+ coordinator.startChain(savedDoc.id());
```

`submitText` and `submitUrl` are replaced by one handler, `POST /api/ingest/capture`, per ADR26
decision 6. It takes a JSON body with either a `url` key or a `text` key, never both, and dispatches
on which is present:

- **`text` present:** create a Document with `content` set to the posted text, `mimeType`
  `text/plain`, no copy row — nothing is on disk — then `coordinator.startChain(saved.id())`.
  `Ingestor.isTextContent` already recognises `text/plain`, so no actuator change is needed on this
  path. The commented-out body at `:171-182` goes; it calls `createDocument("text", text)`, which
  passed a literal as the path column P1.8 removed.
- **`url` present:** create a Document with `sourceUrl` set, `content` empty, no copy row, then start
  the chain. Step 4 is what makes this reach Clipper.
- **Neither, or both, present:** reject the request rather than guessing.

`/api/ingest/text` and `/api/ingest/url` are deleted, not deprecated — two endpoints for one operation
is exactly what ADR26 decision 6 removes.

One shape across all three, per ADR26 decision 7:

```json
{ "id": 42, "status": "ingesting", "message": "Queued" }
```

`/file` keeps `fileName` and `mimeType` as extras. `jobId` does not come back.

The `tags` field all three panels post stays ignored, and ADR27's answer on where tags live drives it
in P1.18. Wiring `linkDocumentToTag` here would build against a UI about to be replaced.

## Commit shape

One branch, one merge, several commits. "Single change" means one delivery, not one blob: commits per
step keep the change bisectable at no cost, and step 0's ADRs commit separately because documentation
does not need the per-commit authorization code does
(`.claude/rules/design-before-implementation.md`).

Suggested boundaries — `0` the ADRs · `1-3` Coordinator and Message · `4-6` endpoints, the actuator
URL field and the page · `7` tests · `8` spike and P1.18.

Only the merge has to be green. Steps 1 to 3 leave `IngestionControllerTest` failing on the old
contract mid-branch, which is fine, and is exactly the state the staged plan papered over with
`@Disabled`.

## Scope boundary

Out, deliberately:

- **P1.18, the composer itself.** Folding it in would add the whole `index.html` rewrite — one
  composer, the URL rule, attachments, the receipt feed, six panels down to three — to a change that
  already touches around a dozen files, and it would break P1.17's no-production-code line. It also
  cannot be planned properly until ADR27 exists. Recommendation: leave it out, create the story in
  step 8, run it next. Including it is defensible if a working screen in this pass matters more than
  the change staying reviewable; it roughly doubles the size.
- **`/api/status` returning zeros.** `getStatusCounts()` is keyed by actuator class name (`Ingestor`,
  `Extractor`) while `StatusController.java:22-26` looks up `ingesting`, `extracting`, `indexed`, so
  every key misses. That is P1.12 entirely. Nothing here fixes it, and nothing here may make it worse.
- **Per-document status for the receipt feed.** The spike records which story owns the endpoint.
- **`/api/search`**, still a stub returning an empty list.
- **`/api/chat/llama`**, which echoes its input. A real reply needs P2.1 and P2.4.
- **Tags wiring.** Ignored by all three endpoints, and it stays that way until P1.18.
- **Ingestor's routing rules beyond the `sourceUrl` change.** A `.txt` goes straight to Indexer,
  skipping the Classifier. Wrong, Phase 2's, not this plan's.

## Risks

- **One merge, wider surface.** The registry going non-static touches every actuator through the base
  class. If injection on the abstract base misbehaves, every routing hop fails at once rather than one
  endpoint failing. Verification 3 exercises all three entry paths for that reason.
- **The spike returns E.** No Java is affected — see the asymmetry table. P1.18's shape changes, and
  that story does not exist yet.
- **Timebox bleed.** The spike is half a day inside a larger change, which is where timeboxes go to
  die. Take B at the halfway mark if A and B are level.
- **ADR26 decision 5 gets deferred quietly.** Two services writing `Document.status` with only one
  synchronized is a live inconsistency, not a tidiness point. Decide it or log it in
  `documents/DESIGN-DEBT.md`; do not leave it as it is for a third time.
