# Bug BUG-005 — The full-path chain runs Classifier before Indexer

## Symptom

A document taking the full path — text or Markdown, not short-circuited the way a URL goes to the
Clipper, an archive to the Extractor, or an unsupported format to a warning — is classified and then
indexed. The required order is the reverse: **`Ingestor → Indexer → Classifier`**, with the file
present in the destination directory once the Indexer has run.

`PipelineFlowTest` asserts the required order and is `@Disabled` against this bug. Enabled, it fails
on the first hop:

```
a full-path document goes from the Ingestor to the Indexer
  ==> expected: <Indexer> but was: <Classifier>
  at PipelineFlowTest.java:99
```

Its second test — that the file is in the destination directory with its content intact — **passes**.
The publishing half is correct; only the ordering is wrong.

## Cause

Not a defect in any one class. Every actuator does exactly what its own design says, and the designs
disagree with the required order:

| Stage | Returns | Set by |
|---|---|---|
| `Ingestor` | `"Classifier"` for text (`Ingestor.java:314`) | **ADR29**, Story P2.2 |
| `Classifier` | `"Indexer"` on every path | **ADR31**, Story P2.4 |
| `Indexer` | `null` — terminal | Story P2.5 |

ADR29 changed the Ingestor's text route from `"Indexer"` to `"Classifier"` on the reasoning that the
Classifier had been registered, threaded and unreachable, and that a document should carry its topic
and tags before it is published. That is a coherent design; it is not the one required here.

The chain is therefore wrong in three places at once, and no existing test noticed. Each of
`IngestorRoutingTest`, `ClassifierTest` and `IndexerTest` asserts one actuator's own decision in
isolation, so all three pass while the chain they compose is not the required one. `PipelineFlowTest`
exists because nothing else states the chain as a whole.

## What has to be decided, not just changed

Reversing the order is three return values, but it moves a real constraint, and the change should not
be made without answering these:

1. **The Indexer publishes; the Classifier then writes to a document that is already in the vault.**
   Today classification happens first, so `document.topic` and the `document_tag` rows exist before
   the file is visible to anything watching the vault. Reversed, a file appears in the destination
   directory first and gains its topic and tags afterwards — a window in which an external indexer
   (Smart Connections, per ADR30) may see an unclassified document.
2. **Does anything downstream of the Indexer need the topic?** `Indexer` logs `doc.getTopic()` in its
   summary line. Reversed, that is always null. Harmless, but it should stop pretending to report
   something.
3. **The Classifier becomes the terminal stage.** It currently returns `"Indexer"` on all five of its
   paths, including every failure path (ADR31 decision D4, which keeps a document moving when
   classification fails). Reversed, those become `null`, and D4's guarantee — a failed classification
   must not strand the document — is satisfied trivially instead, because there is nowhere left to go.
4. **ADR29 and ADR31 both need amending**, not just the code. Both are on file as standalone documents
   (`ADR29-ingestor-boundary.md`, `ADR31-classification-contract.md`) and not yet folded into
   `ADRS.md`, so this is the moment to correct them rather than fold a superseded decision.

## Fix

1. `Ingestor.doTheThing` returns `"Indexer"` for text and Markdown, reverting ADR29's routing row.
2. `Indexer.doTheThing` returns `"Classifier"` on the success path, and `null` where it already stops.
3. `Classifier.doTheThing` returns `null` on every path.
4. Amend ADR29 and ADR31 to record the required order and why it was reversed.
5. Remove `@Disabled` from `PipelineFlowTest`.
6. Update `IngestorRoutingTest`'s "a plain text document routes to Classifier, not straight to the
   Indexer" and the corresponding assertions in `ClassifierTest` and `IndexerTest`.

## Acceptance criteria

- [ ] `PipelineFlowTest` passes with `@Disabled` removed
- [ ] A text document reaches the destination directory and afterwards carries a topic and tag rows
- [ ] A classification failure still leaves the document published rather than stranded
- [ ] The short-circuit routes are unchanged — URL to Clipper, archive to Extractor, unsupported
      formats stopping with a warning naming the format
- [ ] ADR29 and ADR31 record the required order
- [ ] `gradle build` green with nothing skipped

## Notes

Found immediately after P2.1, P2.2, P2.4 and P2.5 were merged, while writing the first test that
describes the pipeline as a whole rather than one stage at a time. The four stories were implemented
in parallel by separate agents, each correct against its own plan; the ordering was settled inside
ADR29 — one story's design gate — rather than in a document about the pipeline, which is how it came
to differ from the required flow without anything catching it.

Worth recording for the same reason: **no test covered the chain before this one.** Adding
`PipelineFlowTest` disabled is still worth doing, because it is the specification and it will fail
loudly the moment someone re-enables it against the wrong order.
