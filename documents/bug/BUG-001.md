# Bug BUG-001 — UI Is Not Showing Up

## Problem

The web UI fails to display when accessing localhost:8080 or localhost:8080/chat. Either no content is served, or the page loads but is blank or shows an error. This blocks all UI-dependent work including Phase 1 testing (smoke tests in P3.4 require a working dashboard), ingestion endpoint testing (P1.13), and any browser-based pipeline observation.

### Symptoms

- Navigate to http://localhost:8080 or http://localhost:8080/chat → no content or blank page
- Browser console shows errors (check Network, Console tabs)
- No HTML content received or 404/5xx error responses
- Static resources (CSS, JavaScript) may or may not load

### Expected Behavior

- UIController routes both `/` and `/chat` to the same HTML template
- Template renders with 7-panel layout (per CLAUDE.md, Phase 1 deliverables)
- REST API client (client.js) is available and wired to forms
- Page is interactive: file upload, text input, URL input forms all respond to clicks

## Root Cause Analysis

Investigate:

1. **UIController routing** — Does it exist? Are both `/` and `/chat` mapped?
2. **Template location** — Is the template file in `src/main/resources/static/`?
3. **Spring configuration** — Is Spring configured to serve static resources from that location? Check `application.yaml`.
4. **Build output** — Does `gradle build` include static resources in the JAR? Check `build/resources/main/`.
5. **Server startup logs** — Any errors during context refresh? Any 404s in the log when you navigate?

## Acceptance Criteria

- [ ] UIController has methods handling both `GET /` and `GET /chat`, returning the same template
- [ ] HTML template (`index.html` or `chat.html`) exists at `src/main/resources/static/`
- [ ] Spring serves static content from `classpath:/static/` (default behavior, verify in `application.yaml` if overridden)
- [ ] `gradle bootRun` starts without errors in the controller layer
- [ ] Navigating to http://localhost:8080/chat in a browser returns HTML with the 7-panel layout visible
- [ ] Console (F12) shows no 404s for static resources (CSS, JS files)
- [ ] At least one form (file upload, text input, or URL input) is present and clickable
