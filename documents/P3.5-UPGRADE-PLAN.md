# P3.5 Upgrade Plan

Execution plan for Story P3.5 (Upgrade to JUnit 5).

## The story is out of date

P3.5 was written as a migration. It is not one. Verified against the working tree on 2026-09-07:

| P3.5 requirement | State |
|---|---|
| Replace `junit:junit:4.x` with `org.junit.jupiter:junit-jupiter` | **Not done** — `build.gradle:46` still declares `junit:junit:4.13.2` |
| Replace `@RunWith` / `@Rule` | Nothing to replace — zero occurrences in the repository |
| `@Test`, `@DisplayName`, lifecycle annotations | Already Jupiter — `ActuatorManagerTest.java:4-12`, `IngestionControllerTest.java:6-8` |
| Spring Boot test annotations under Jupiter | Already so — `@SpringBootTest` / `@WebMvcTest`, no runner |
| Mockito integration | Already so — `@MockBean` + static `Mockito.*`, no `MockitoJUnitRunner` |
| Remove JUnit 4 imports | Nothing to remove — no `org.junit.Test`, `org.junit.Assert`, `@RunWith`, `@Rule` or `junit.framework` anywhere |
| `gradle test` runs on the Jupiter engine | Already so — `build.gradle:49-51`, `useJUnitPlatform()` |

Both test classes are Jupiter already. The `org.junit.jupiter:junit-jupiter` dependency the story
asks for is already on the test classpath, pulled in transitively by
`spring-boot-starter-test` (`build.gradle:45`).

## What is actually wrong, and why it matters

One line: `testImplementation 'junit:junit:4.13.2'` (`build.gradle:46`).

There is no `junit-vintage-engine` on the classpath, and `useJUnitPlatform()` is set with no engine
selection. So JUnit 4 is present as an **API with no engine behind it**. A test written with
`org.junit.Test` compiles cleanly, produces no warning, and is then **silently not executed** —
Gradle reports the class with zero tests rather than failing. That is the failure mode this story
removes, and it is worse than a broken build because it looks like a pass.

The story's own framing ("Migrate all test code…") hides this. The value is not migration, it is
closing a silent-skip trap before Phase 3 writes real test suites against it (P3.1–P3.4).

## The change

```diff
   // Testing
   testImplementation 'org.springframework.boot:spring-boot-starter-test'
-  testImplementation 'junit:junit:4.13.2'
```

One deleted line. Nothing else in `build.gradle` moves — `useJUnitPlatform()` stays, and
`spring-boot-starter-test` continues to supply Jupiter, AssertJ, Mockito, Hamcrest and
`spring-test`.

## Adjacent finding — `@MockBean` (recommend including; separable)

`IngestionControllerTest.java:11` imports `org.springframework.boot.test.mock.mockito.MockBean`.
That annotation has been deprecated since Spring Boot 3.4 and is removed in Spring Boot 4. This
project is on Spring Boot 3.5.6 (`build.gradle:3`), so it compiles today with a deprecation warning
and will break the first time the Boot version moves.

Replacement is mechanical, two occurrences in one file:

| Before | After |
|---|---|
| `import org.springframework.boot.test.mock.mockito.MockBean;` | `import org.springframework.test.context.bean.override.mockito.MockitoBean;` |
| `@MockBean private DatabaseService databaseService;` | `@MockitoBean private DatabaseService databaseService;` |
| `@MockBean private Coordinator coordinator;` | `@MockitoBean private Coordinator coordinator;` |

This is not JUnit 4, so it is strictly outside P3.5 as written. It belongs to the same "testing
infrastructure modernization" note the tracker already attaches to P3.5, it touches the same file,
and splitting it into its own story costs more than doing it. **Recommendation: fold it in and say
so in the story's changelog.** If it is split instead, it needs a story of its own before P3.1 adds
more `@MockBean` uses.

## Sequencing against P1.11

P1.11's plan disables several `IngestionControllerTest` methods and rewrites `ActuatorManagerTest`.
Both stories touch the test tree, but not the same lines — P3.5 touches `build.gradle` and two
import/annotation lines. Either order works. Running P3.5 **first** is marginally better: it is
fifteen minutes, and it means P1.11's new `CoordinatorTest` is written on a classpath that cannot
silently swallow a JUnit 4 import.

## Verification

1. Record the baseline first: `scripts/build-log.ps1 -Task test`, and note the executed test count
   from the report (`build/reports/tests/test/index.html`).
2. Apply the change.
3. `scripts/build-log.ps1 -Task test` — passes, and the executed test count is **identical**. A drop
   means something was relying on the JUnit 4 API; an increase means something was being skipped and
   the trap was already live.
4. Confirm the JUnit 4 jar is gone from the test runtime:
   `.\gradlew dependencies --configuration testRuntimeClasspath` shows no `junit:junit`.
5. Sanity-check the trap is closed: temporarily add a test class using `org.junit.Test` and confirm
   it now **fails to compile** rather than reporting zero tests. Delete it afterwards.
