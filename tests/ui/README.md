# UI Test Suite

Automated browser-based test suite using [Playwright](https://playwright.dev/) for 4thBrain's web UI.

## Quick Start

### Prerequisites

- Node.js 22+ (required for `node:sqlite` support)
- npm 10+
- Both root and `server/` dependencies installed

### Setup

```bash
# Install root dependencies
npm ci

# Install server dependencies
cd server
npm ci
cd ..

# Install Playwright browsers
npx playwright install --with-deps
```

### Run Tests

```bash
# Run all tests
npm run test:ui

# Run only functional tests (no visual diffs)
npm run test:ui:functional

# Run a specific test file
npx playwright test tests/ui/core.spec.js

# Run with headed browser (see what's happening)
npx playwright test --headed

# Run with headed browser + debug mode
npx playwright test --debug

# Run a specific test
npx playwright test -g "chat shell layout"
```

### View Test Report

After running tests:

```bash
npx playwright show-report
```

This opens an HTML report with screenshots, traces, and detailed failure information.

## Test Isolation

Tests run against an isolated copy of the application:

| Env Var | Purpose |
|---------|---------|
| `FOURTHBRAIN_PARAMS_FILE` | Points to a test `params.json` with isolated vault/raw dirs |
| `FOURTHBRAIN_DB_PATH` | Points to a test SQLite database (not the real production DB) |
| `FOURTHBRAIN_PORT_OVERRIDE` | Allows tests to run server on port 3100 instead of 3000 |
| `FOURTHBRAIN_TEST_HARNESS` | Marker that triggers safety checks (env vars must be set) |

**Why this matters:** The real `params.json` points to your actual Obsidian vault. The job-queue poller writes into `vault_dir/incoming` and `vault_dir/raw`. Without isolation, a test run would modify your real vault and database. The env var overrides ensure every test run is completely isolated.

Tests automatically clean up their isolated database and file tree between runs.

## Updating Snapshots

Visual regression tests compare against baseline screenshots. When you intentionally change UI styling:

### On macOS/Linux:

```bash
# Update snapshots (uses Linux rendering for CI compatibility)
npx playwright test --update-snapshots
```

### On Windows without Docker:

If you don't have Docker installed, use the CI failure artifact method:

1. Push a branch with your UI changes
2. Wait for the GitHub Actions "UI Tests" workflow to fail on visual diffs
3. Download the "playwright-report" artifact from the workflow run
4. Find the `actual` screenshot in the report
5. Copy the actual screenshot filename and update the corresponding baseline locally
6. Commit the updated baselines

Alternatively, install the [official Playwright Docker image](https://playwright.dev/docs/docker):

```bash
docker run --rm -v %cd%:/work mcr.microsoft.com/playwright:v1.46.0-jammy bash -c "cd /work && npm ci && npx playwright test --update-snapshots"
```

## Debugging

### See what's happening

```bash
npx playwright test --headed
```

Opens a real browser window so you can watch the test run.

### Step through a test

```bash
npx playwright test --debug
```

Opens the Playwright Inspector, where you can step through each action.

### Enable trace recording

Traces are automatically saved on failure (`trace: "retain-on-failure"` in config), so you can replay exactly what happened.

## Adding New Tests

### Test File Structure

```javascript
const { test, expect } = require("@playwright/test");
const { gotoPanel, collectConsoleIssues } = require("./helpers");

test.describe("Feature name", () => {
  test("specific behavior @visual", async ({ page }) => {
    // @visual tag = this test includes a visual snapshot
    // Remove the tag if the test has no snapshots
    
    await page.goto("/chat");
    
    // Test logic here
    
    await expect(page).toHaveScreenshot("descriptive-name.png");
  });
});
```

### Naming Conventions

- **Test files:** `{feature}.spec.js` (e.g., `core.spec.js`, `ingestion.spec.js`)
- **Snapshots:** `{test-name}-{project}-{platform}.png` (auto-generated by Playwright)
  - Example: `chat-shell-desktop-chromium-linux.png`
- **Test names:** Clear, describe the behavior (e.g., "chat shell layout loads without console errors")

### Helper Functions

Available in `tests/ui/helpers.js`:

```javascript
// Navigate to a sidebar panel
await gotoPanel(page, "add-text");

// Collect console errors/exceptions that occurred
const issues = await collectConsoleIssues(page);

// Assert no horizontal scroll on mobile viewport
await assertNoHorizontalOverflow(page);

// Generate unique names for test data
const testTag = uniqueName("e2e-test");  // "e2e-test-1693421234-abc123"
```

## Test Structure

### Projects

Tests run in two projects:
- **desktop-chromium** — full resolution, visual snapshots
- **mobile-360** — 360px viewport, responsive design verification

Tests tagged with `@mobile-360` run only in the mobile project.
Tests tagged with `@visual` are excluded from `npm run test:ui:functional`.

### Test Categories

| File | Purpose |
|------|---------|
| `core.spec.js` | Landing redirect, shell layout, panel navigation |
| `mocked-panels.spec.js` | Mocked status panel and llama chat |
| `ingestion.spec.js` | File/text/URL ingestion job creation |
| `admin.spec.js` | Admin panel table browser, CRUD operations |
| `api-docs.spec.js` | API documentation page and openapi.json validation |
| `dev-gating.spec.js` | Verify dev-only routes return 403 in prod mode |
| `mobile.spec.js` | Mobile viewport responsiveness |

## Running Tests

Tests are run manually on your machine via `npm run test:ui` or through the Playwright CLI. There is no automated CI/CD pipeline — all test execution is local.

## Troubleshooting

### "Port 3100 is already in use"

A previous test run's server didn't shut down cleanly.

```bash
# Kill the process on port 3100
# On Windows:
netstat -ano | findstr :3100
taskkill /PID <PID> /F

# On macOS/Linux:
lsof -i :3100
kill <PID>
```

Then retry:

```bash
npm run test:ui
```

### "Timeout waiting for webServer"

The test server failed to start. Check:

1. Port 3100 is free (`netstat -ano | findstr :3100`)
2. `server/` installs correctly (`npm ci` in `server/`)
3. `params.json` exists at repo root
4. Node.js is version 22+ (`node --version`)

### Visual diffs on every run

This usually means baselines were generated on Windows and tests run on Linux (or vice versa). Font rendering differs between platforms.

**Solution:** Regenerate baselines on the target OS (Linux in CI, so use Docker on Windows).

### Tests hang or timeout

Check if the server is stuck:

```bash
# See if server process exists
ps aux | grep "node index.js"

# View server logs
npx playwright test --debug  # Opens the Inspector
```

## Best Practices

1. **Keep tests deterministic** — avoid sleeps; use `waitFor()` instead
2. **Use stable selectors** — prefer `data-testid` or `data-panel` over brittle `.class` or `:nth-child()` selectors
3. **Isolate test data** — use `uniqueName()` to create unique tags/names; clean up in `afterAll()`
4. **Test behavior, not implementation** — assert what the user sees, not internal state
5. **Avoid overlapping state** — each test should be independent; use isolated DB and clean temp directory
